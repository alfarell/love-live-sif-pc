# M1: archives (`ARC\0` / `cmp\0`)

Created: 202610311955 (Asia/Jakarta). Plan: `plan/202610311831-sif-port-roadmap/202610311831-plan.md`, milestone M1. Format spec: `repository/docs/formats/arc.md`.

## 1. Results

| Item | Result |
|---|---|
| U1 `cmp\0lzma` variant | **Solved.** LZMA-alone stream without the 8-byte size field (props `5d`, 64 KiB dictionary). Inserting the unpacked size after the 5 props bytes lets Python's `lzma.FORMAT_ALONE` decode it; `common/common.pac` → 54,705,664 bytes, an `ARC\0` with 0x18 entries |
| U2 ARC payload offset | **Solved.** Entry data = u32 size, u16 header length (0x80; 4 in 4 cases), u16 flags (1 ⇔ payload is `cmp`, 8,248/8,248). Part 9's "data+8" was wrong; the payload starts at data + 0x80 |
| Parse coverage | **3,552/3,552** `.pac` files parse (16,650 ARC tables, 119,372 listing rows, 97,980 leaf files, nesting depth ≤ 3). Before M1: 2 files failed and payloads were misread |
| Name hash | **Solved.** `h = h*33 + c` from 0, then `h + (h >> 5)` (32-bit). 83,998/83,998 named entries match |
| Hidden names | **None to recover.** All 27,080 nameless entries have hash 0 (`SHP`/`SARC` shader parts, 4 `message.pac` sub-tables) |
| Extraction | `pac_extract.py` tested on 43 archives (1,114 files, 0.52 GB in `work/extract/`); file count equals the listing's leaf count (1,033 = 1,033 for the first 42). The full run (≈20.9 GiB) is waiting for user approval (rule 6) |

How the hash was found (no disassembly needed): for names differing by +1 in one character, the hash difference by position from the end is 1, 34, 1123, 37060, 1222981, ... (each 33 × previous + 1, `work/pac-list.csv`). That is 33^k × 33/32, the shape of djb2 followed by `h += h >> 5`. The final fit was checked on every named entry (`tools/arc_names.py work/pac-list.csv`).

Bugs fixed in `pac_list.py` along the way:
- empty nested tables (count 0, e.g. inside `chr/c11/c11.pac`) crashed the offset check;
- the header-length field is a u16 (`0x00010080` = length 0x80 + flags 1).

## 3. Notable observations for M2

- **Inner formats** now visible: `tex` → `btx\0` (40,101), `scd` → `Scor` (11,589), `btl` → `BTL\0`, `mot`/`mdl` → `BMAR`, `bin` → `BLBN` (1,698) / Iggy (36), `canm` → `BSCM`, `efx` → `01 02 08 05`, `SHP` (no magic) + `SARC` (text).
- **`acb` entries are mostly `ACGP`, not CRI `@UTF`** (1,229 vs 3). Hypothesis: `ACGP` is a game-own container (it sits next to `mot` motions, e.g. `mot_11_chika_001_stand.acb`), so "acb" here may not mean CRI cue sheet. Check before `acb_dump.py`.
- **`FirehawkArchiveDatas`**: the archive name inside effect `.efx` entries (`effect/ef2_en.pac`). Hypothesis: "Firehawk" is the effect tool or runtime name; search the eboot strings in M2.
- Record field 0x04 looks like an ID (812 for `ef_812_*`); 0x06 equals the entry index in the samples. Not needed for reading.
