## 1. What is inside the `.pac` archives (new in this part)

`py -3.14 -I repository\tools\pac_list.py "<SIF>\CUSA24620" work\pac-list.csv --max-depth 3`.

**Layout (Hypothesis, checked by asserts in the script on all but 2 files):**

| Offset | Content |
|---|---|
| 0x00 | `ARC\0` |
| 0x04 | u16 `0x0100` |
| 0x06 | u16 count (repeated) |
| 0x10 | archive name (32 bytes) |
| 0x30 | u32 data offsets (one per entry) |

- Entry records follow, aligned to 0x20: 4-byte type tag, index, u32 name hash, name length, name; each record is padded to 0x20.
- Data starts with a u32 size.
- Hex evidence: `live/0010/0010.pac`, `talk/talk.pac` (21 entries), `message/message.pac` (Part 9 dumps).

**Result:**
- 13,497 entries; nesting depth 1 (3,264 nested entries, all in `message/`).
- 2 files fail: `common/common.pac` and `common/common2.pac`. They are `cmp\0lzma`, and Python's LZMA-alone decoder rejects them ("Corrupt input data"), so the LZMA variant differs (Open question 1).
- Not solved yet: the second u32 at each data start. Payload magic read at data+8 is mostly zeros, so the real payload offset differs (for example 0x80 in `0010.pac`). Many entries carry only a name hash, with an empty name.

## 4. Plan C fallback: imports vs shadPS4 (from `sif-shadps4-coverage.csv`)

Across 1,028 import rows (eboot + 3 shipped modules): **645 implemented, 74 stub-marked, 309 missing**. The 309 missing are `libc` (62 eboot rows), `libSceNpToolkit2` (181), `libSceFios2` (11), `libSceLibcInternal` (14 + 23), `libSceNpManager` (7) and libkernel imports of the shipped modules (3). Most are served by SIF's own `sce_module/` libraries, which shadPS4 loads as guest code (decision record §2).

**eboot imports by library (implemented / stub / missing):**
- libkernel 67/0/0;
- GNM 74/13/0; VideoOut 13/0/0; SaveData 12/0/0; Pad 5/1/0; AppContent 4/2/0; AudioOut 3/3/0;
- dialogs implemented;
- PlayGoDialog 0/6/0; ScreenShot 0/4/0; SharePlay 0/3/0; GameLiveStreaming 0/3/0.

**Stub-marked eboot imports that matter (from the CSV):**
- **GNM:** `sceGnmDrawIndexMultiInstanced`, `sceGnmDrawOpaqueAuto`, `sceGnmFlushGarlic`, `sceGnmGetEqTimeStamp`, mip-stats and wave-limit calls.
- **AudioOut:** `sceAudioOutOutput`, `sceAudioOutOutputs`.
- **Other:** `scePadInit`, `sceAppContentInitialize`, `sceUserServiceInitialize2`.

**Caveat:** the stub marker is a heuristic. A body that logs `(STUBBED)` on one rare branch counts as a stub. `sceAudioOutOutput` is almost certainly functional in shadPS4, for example. Check by reading those bodies before relying on them.

## 6. First things that would stop SIF from showing its first screen

### Plan A (native rewrite)

1. **Reading the boot data:** `common/common.pac` uses the failing LZMA variant (U1), and its name suggests boot-wide data. Payload offsets (U2) block every archive.
2. **Textures:** no title/logo image can be drawn until `tex`/`btx` decoding (and detiling, if any) works (U4).
3. **UI layout runtime:** the title and top menu are Flash-based UI (`ui2/00_common*.pac`, `.iggy`). Without a UI runtime (U3) only placeholder screens are possible.
4. **Fonts and messages:** `font.pac` and `message.pac` (`bin` tables) for any text.
5. **Boot flow:** the `sqBoot` → `sqTitle` → `sqTopMenu` order and what each loads (S01; read from the eboot).
6. **Audio for the title screen:** ACB cue lookup + HCA decode (U7). Not strictly needed for a first frame.

### Plan C (if it ever boots in shadPS4)

1. Stub-marked GNM draw paths (`sceGnmDrawIndexMultiInstanced`, `sceGnmDrawOpaqueAuto`) if the title screen uses them.
2. `scePadInit` / `sceUserServiceInitialize2` behaviour.
3. NpToolkit2 start-up (guest library) against stub-heavy NP services; the game must tolerate "not signed in".
4. PlayGo dialog stubs (the game imports 6 `scePlayGoDialog*` calls).
5. Unknown until a real run: the C probe (decision record §4) answers this.
