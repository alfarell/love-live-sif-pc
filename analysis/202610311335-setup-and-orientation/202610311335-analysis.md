## 6. Caveat about read-only access

I ran `git status --short` in pt-pc once without `--no-optional-locks`. Git may refresh the stat cache in `.git/index` during `status`; this does not change tracked files, commits, or the working tree, but it can rewrite `.git/index`. Later commands used `git --no-optional-locks`. All later parts should use `git --no-optional-locks` (or only `log`/`show`/`ls-files`) in pt-pc.
