Created: 202610312056 (Asia/Jakarta). Follows `202610312044-analysis.md` (same topic). The user chose "Read BMAR first" before the CP1 decision. Format page: `repository/docs/formats/bmar.md`. Tool: `repository/tools/bmar_dump.py`.

## 1. Results

| Item | Result |
|---|---|
| Container | `BMAR104` + ARC "BladeModelPac" with parts `BML` / `BMA` / `BMD` / `BMT`. All 8,241 files parse (3,534 models, 4,707 motions) |
| Chunks | Tag + u32 size + u32 `0x00040000` + body, 4-aligned, ends `POF0` + tag 0; u64 pointers into `DATA` bodies |
| Scene graph | `NODE`: TRS with R = Rz·Ry·Rx, parent index at +0x60 (206/206 match names). Model space Z-up; root `bml_axisNode` converts to Y-up |
| Meshes | `MESH` + `DRAW` (node, mesh, material) + `MATE` + `TXTR`. **All 27,392 meshes**: stride = format size + 4 × extra count |
| Vertex formats | 16 format codes, 22 format/stride pairs; per-bit sizes solved (f32 vs f16 variants of normal, uv, tangent, binormal; 40-byte skin block) |
| Skinning | 4 float weights (sum 1.0) + 4 u8 bone indices per vertex; palette in `MTXP` |
| Visual check | `work/models/chika.png`: bind-pose T-pose body, face, eyes, hair in place. `work/models/stage_cull1.png`: st017 live hall interior (truss, lights, arch stage) matching its cubemap texture |
| Motions | `ANHD` (version 103, 60 fps, frame count), `ANSK` track table (node name, name hash = `NODE` +0x5C, 3 channels with key count and type). Keyframe encoding not decoded (M5) |

Two corrections on the way:
- My first vertex table broke on 11,222 meshes. It assumed one encoding per attribute and missed the +0x4C extra count. It was fixed by solving bit sizes from the full format/stride list.
- The first preview of the stage showed only the outer wall. Backface culling was needed, and it also settled the winding order.
