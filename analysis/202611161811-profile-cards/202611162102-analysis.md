## Correction to the first pass: string addresses

`work/eboot-strings.txt` lists **file offsets**, not addresses. The ELF's first segment maps file offset 0x4000 to address 0 (program header 0: `off 0x4000 va 0x0`). So **a string's address is its file offset − 0x4000**. The first pass searched for references with the file offsets, which is why it found almost none. Its claims that came from those searches are wrong:

| First-pass claim | Fact |
|---|---|
| `FUN_00084c70` (`0x84D7C`) loads `ll3::s_preset_profilecard` | wrong: that `lea` points at another string. The presets are read by `FUN_001f0d50`/`FUN_001f0d90` (below) |
| The debug save display at `0x20CB31`-`0x20FE4A` holds the Proca counters | wrong: those `lea`s point elsewhere. The counter strings are used at `0x1C3890` (`FUN_001c3ca0`'s area) |
| Strings are reached "indirectly" | wrong: with the right addresses, plain `lea` references exist (e.g. "proca_preset/%s", address `0x5F63D0`, used at `0x1F1106` and `0x1F1346`) |

*For later work:* an address from `eboot-strings.txt` must have 0x4000 subtracted before searching `work/eboot.asm`. Earlier milestones that quoted string locations used them as file offsets for reading bytes, which is correct as such.

## The NPC support cards (`FUN_001d63d0`)

Called when a live is prepared, with `param_2` = the group being played (the µ's/Aqours mode).
1. **Skip:** the NPCs are not picked when `FUN_001ccfc0` (on the object at `DAT_00e045f0`, vtable +0x48) is false or `FUN_001ccfe0` (vtable +0x50) is true. *Hypothesis:* "online and Receive Everyone's Profile Cards ON" uses real cards instead. Offline, the NPCs are always used (P2 saw them each time).
2. **Candidates:** every preset (`FUN_001f0d50` = count, `FUN_001f0d90(i)` = record) whose member card's member (`s_member_card_datas +0x10`, via `FUN_00010770`) is in the played group. The group is `FUN_0001ead0(member)` = `member > 9 ? 1 : 0`, so µ's members 1-9 are group 0 and Aqours and Saint Snow (11-22) group 1. That is 9 candidates for µ's and 11 for the other group.
3. **Two different picks**, when there are at least 2 candidates:
   - Each pick is `index = (int)((x >> 16) × (1/65536) × n)`, where `n` is the number of candidates left and `x` the next xorshift128 value.
   - The generator is a static state, set once per game run to `{0, 1, 1812433255, 1900727105}` (`0x5F55A0`, file offset `0x5F95A0`); the scale 1/65536 is at `0x5F55C4`.
   - Step: `t = s0 ^ (s0 << 11); s0 = s1; s1 = s2; s2 = s3; s3 = s3 ^ (s3 >> 19) ^ t ^ (t >> 8)`.
   - The first pick is removed from the list before the second.
4. **Each pick** goes through `FUN_001f1210`:
   - it builds a support player from the preset: frame, accolade, badge, plate and member card into the player record;
   - it sets the NPC flag `+0x51 = 1`, the flag S6 saw skipped by the skill-card drop;
   - it loads the card picture `proca_preset/<file>` (the record's string at +0x38) as a texture.

**Port:** the same filter and draw; the xorshift128 is a few lines. Because the state carries over within a game run, which NPCs appear depends on how many lives were played since start. P2 saw Nico + Maki (M11) and Nico + Umi (M12).

## Save fields named by the game's own debug dump (`FUN_00218660`)

The debug menu prints the save with field names ("LiveViewSS", "MyProca", "OtherProca").

**Photo ("LiveViewSS")**, one per slot, the 0x100-byte records at main save +0x60000 (P2):

| Offset | Name |
|---|---|
| +0x00 | stageid (1 in P2: Live Show Stage) |
| +0x04 | membercardid |
| +0x08 | liveid (340011) |
| +0x0C | favorite |

**MyProca**, the record at main +0xA0 (P2):

| Offset (from +0xA0) | Name |
|---|---|
| +0x0C | frameid |
| +0x10 | liveid |
| +0x14 | membercard id |
| +0x18 | favorability (the Friendship level drawn in the heart) |
| +0x1C | honor (the accolade) |
| +0x20 | badge |
| +0x24 | nameplate id |
| +0x28 … +0x3C | skill (0-2): id, lv |

- **"OtherProca":** the same fields in a list at main +0x5CD24 (the received cards), plus a favourite flag.
- **liveid:** the live's id, the song and its live variant (340011 for Susume→Tomorrow). The card shows the song name and the costume from it.
