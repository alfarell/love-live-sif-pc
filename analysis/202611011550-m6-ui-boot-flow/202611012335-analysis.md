# M6: the top menu and `message.pac`, what they need

Created: 202611012335 (Asia/Jakarta). Follows `202611011642-analysis.md`. Source: `ui2/10_top_menu_en.pac` (73 MB unpacked, extracted to `work/extract/`) and `message/message.pac`.

## 1. Top menu (`10_top_menu_en`)

- 11 layouts and 11 parts. `uil0001_TopMenu00` places:
  - the room background (`uip0001_RoomBG00`);
  - the menu background and its effect;
  - the main menu list (`uil0002_MenuList00`);
  - four submenu lists, each in an idle and an active (`_act`) form;
  - the player data header (`uil0009_PlayerDataTop00`).
- New layout features, compared with the title:

| Feature | Example | Needed |
|---|---|---|
| **Nested layouts** | `uil0001_TopMenu00` places `uil0003_SubMenuList00` | `DrawLayout` recursion |
| **Numbered instances** | `uip0005_SubMenuList00_00` … `_04`, `uip0004_MenuIcon00_00` … | Strip the `_NN` suffix to find the part; each instance has its own state (label, highlight) |
| **Parts of other packages** | `common_uip0023_com_clear_text00` (00_common), `ctg03_uil0005_NameSet00`, `ctg03_uip0004_Title00` (03_card) | Prefix → package lookup |
| **Atlas labels** | `menu_icon0Shape0` uses `top_mode_main00_T.png` with UVs (0–0.25, 0–0.25): one cell of a 4 × 4 label atlas; the banners likewise (`top_mode_main_banner00_T`, 4 × 8) | A per-instance UV offset chosen by the menu code |
| **Material and visibility tracks** | Clip `uip0004_MenuList00_a003`: `ANMT` (16-byte header: table*, u16 count 2, u16 4) and `ANVS`; `a004` also has `ANSK` | Decode `ANMT` (UV or colour keys, *Hypothesis*) and `ANVS` (mesh visibility, *Hypothesis*) |
| **Menu logic** | Which atlas cell each entry shows, the submenu per entry, the selection and decide animations (`uip0020_SubMenuselect00_a003`, `uip0021_SubMenusdecide00_a006` are clip-only parts) | Eboot screen code (top-menu state machine) |

The sky/room background, the menu background and the ring textures are plain parts and would draw today.

## 2. `message/message.pac`

- Header u32 4, then an ARC of 4 language packages: `common_msg_4` (Japanese), `common_msg_5` (English, *Hypothesis* from "English Not Defined" placeholders), `common_msg_6` (simplified Chinese), `common_msg_7` (*Hypothesis:* traditional Chinese).
- Each package has 816 nameless entries. Each entry is one message table:
  - u32 4, u32 ?, u16 size, u16 × 3 counts;
  - then tables of **self-relative** u32 offsets (many entries point to the same place, *Hypothesis:* per-character attribute runs);
  - then the text.
- The Japanese text is plain UTF-8 (e.g. `ラブライブ！スクールアイドルフェスティバ…`). The English entries hold text in another encoding, not yet identified.
- Which table and index a UI text box uses is decided in eboot code (not traced).

## 3. Assessment

The title screen needed only parts and layouts. The top menu, song select (`20_setup`) and result (`95_result`) need all of §1 plus the menu logic per screen from the eboot. This is the "screens and systems" breadth that CP3 is meant to estimate (decision record §4: CP3 "at CP2", moved by the roadmap to the start of M6).
