# M6: the UI system (U3 resolved)

Created: 202611011550 (Asia/Jakarta). Roadmap M6: "U3 resolved; UI runtime for the needed formats; boot → title → top menu → song select → live → result; CP3 inventory". Sources: `work/pac-list.csv`, `work/eboot-strings.txt`, `work/elf/eboot.elf`, and `ui2/01_title_en.pac` extracted to `work/extract/`.

## 1. U3: no Flash runtime is needed

There are two UI data sets in the dump:

| Set | Content | Used by the PS4 game? |
|---|---|---|
| `ui2/NN_<screen>[_cn/_en/_tw].pac` (13 screens × 4 languages; 80_skill_card has no variants) | BMAR layouts and parts, animation clips, `BTL` timelines, `BLBN` tables, btx textures | **Yes.** The eboot has the table names (`ui_locator.bin` / `s_ui_locator_info_table`, `ui_parts.bin`, `ui_text.bin`, 0x5FE873…) and part names (`uil0004_CardPoint00_%02d`, `uip0012_CreatePossible00`) |
| 36 Iggy movies (`49 67 0A ED`) in `ui/ui_setup.pac`, `ui/ui_result.pac`, `ui/ui_talk.pac` (`swf.pac`) | Flash UI (RAD Iggy) | **Probably not** (see below) |

Evidence that the Iggy movies are unused:
1. The eboot has no Iggy runtime: no Iggy or RAD strings, and no Iggy magic number anywhere (M0 analysis).
2. No movie name appears in the eboot strings (`talk_window`, `music_select_main`, `satellite_result_main`, …: 0 hits).
3. `ui/ui_setup.pac`, which holds 29 of the 36 movies, is never named.
4. The movie names point to the arcade cabinet ("satellite" screens).

`ui/ui_result.pac` and `ui/ui_talk.pac` are named in a package table (file 0xA329B0, records of pointer + flags: ingame 0x101, result 0x1, talk 0), so the game loads them, probably for their textures.

*Status:* strongly supported, but the loader code is not traced. The PS4 setup and result screens have their own `ui2` layouts (`20_setup`, `95_result`).

The `ui2` system can therefore be rendered with what the port already has (BMAR, btx). This removes the R1 risk ("UI runtime is a full Flash player").

## 2. The `ui2` layout format (from `01_title_en.pac`)

| Item | Content |
|---|---|
| `uipNNNN_<Name>.pac` (part) | One BMAR with textured **quads** (format `0x125`, 4 vertices, 2 triangles, pixel units, centred on the part origin) plus `animation.pac` (clips `<part>_aNNN.bmarc`) and `timeline.pac` (`BTL`). Its own `texture.pac` may hold its textures |
| `uilNNNN_<Name>.pac` (layout) | A BMAR without meshes: one node per placed part, named after the part (`uip0011_TitleBG00` …), with its position |
| `texture.pac` | btx textures of the screen; material texture names end in `.png` |
| `ui_parts.bin` | `s_ui_parts_info_table`: (u64 id, name*) for each part, e.g. 10 → `TitleLogo00` |
| `ui_locator.bin` | `s_ui_locator_info_table`: (u64 id, name*) for each layout, e.g. 2 → `MainTitle00` |
| `ui_text.bin` | `ll3::ui::s_ui_text_info_table`: text boxes, records with a part id, 28/97 (*Hypothesis:* font size), and a string* (`Version 1.01`); plus `s_test_str_*` |

- **Canvas:** 1920 × 1080 pixels, origin at the top-left, **y negative downwards**. In `uil0002_MainTitle00` the background sits at (960, −540) and is 1920 × 1080. The logo is at (960, −460), "Game Start" at (960, −869) and the copyright at (960, −985).
- **UVs:** v = 0 is the texture's top row.
- **Text boxes:** a quad with an empty texture (`_text00`, material `lambert1`) is a text box.

## 3. What the screens contain (title, `01_title_en`)

The flow order, inferred from the part names:
1. CRI logo (`uip0005`);
2. Square Enix logo (`uip0006`);
3. Notice (`uip0001`, `tit_adv_caution`);
4. Title (`uil0002` MainTitle: BG + logo + "Game Start" with clip `a003`, *Hypothesis:* blinking + copyright);
5. Name entry and member select (`uil0050`–`0052`, `uip0050`–`0057`) for a new save.

Timings and transitions are in the eboot's screen code and the `BTL` timelines; neither is decoded.
