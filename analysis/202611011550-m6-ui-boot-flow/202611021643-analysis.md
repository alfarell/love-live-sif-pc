# M6: LIVE CLEAR and the `.fad` colour add

Created: 202611021643 (Asia/Jakarta). Follows `202611021616-analysis.md`.

## 1. Colour add in the UI shader

`.fad` colour transforms have a multiply part and an add part. Flags bit 1 marks the add; it is used in LIVE CLEAR for a brightening flash, e.g. add (19, 19, 19, 0) rising to (54, 54, 54, 0).

`shaders/ui.frag` now computes `texture × tint + add`, clamped to 0–1, from a third uniform vector. `Renderer::DrawUiMesh` gains an `add` parameter (default 0), and `DrawFad` passes the transform's add.

## 2. LIVE CLEAR

- `ui_ingame_end_text_liveclear.fad`: 200 frames (3.33 s), 11 sprites. The text (1056 px wide, starting at 2.5× scale) zooms in, with bubbles and notes.
- **Anchor:** the layout table's `layout_FULLCOMBO` entry ((962, 500), 1052 × 147), the one banner spot of that size (*Hypothesis*).
- **When:** from the moment every note is judged, timed by the wall clock (the audio clock stops with the music). The screen fades out once the animation's 200 frames are over. This replaces the old "3 s after the last note, or the music stopped" rule.
- It is drawn over the combo counter.
- `Playfield::LoadFad` now loads any `anim.pac` file plus its textures; the judgement animations use it too.
