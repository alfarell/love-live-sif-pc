## 1. Format

`.fad` is a Flash-like 2D timeline. The full spec is in `repository/docs/formats/fad.md`. In short:
- **Header:** 24 bytes: version 1, a 0–400 × 0–400 canvas, 60 fps, and the frame count.
- **Records:** u8 tag, `0xAA`, u16 length in 16-bit words (header included), payload.
- **Tags:**
  - `09` texture names;
  - `02` shape (texture id + size);
  - `03 … 00` one-frame sprite (one shape, centred);
  - `04` place, `07` remove;
  - `05` matrix (a, d, b, c, tx, ty);
  - `06` colour transform (multiply in 8.8 fixed point, add);
  - `08` show frame.

How it was decoded: starting from MISS, the smallest file. Its single texture is 140 × 72, and the first matrix is (−70, −36), the texture's half size. Its colour alpha falls 255 → 0 over frames 10–24. Then the framing was checked against all nine files: each parses exactly to its end, and each main timeline has the header's frame count. GOOD and PERFECT showed the rings centred on the canvas centre (200, 200), with the arched text above it.

New: `tools/fad_dump.py` (dump and per-tag summary), `src/engine/formats/fad.{h,cpp}`, `tests/unit/fad_test.cpp` (`sif_fad_test <dump>`). The test checks the MISS values from the dump, and the frame count of six files.
