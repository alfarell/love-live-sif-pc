# M6: screen load time (vfs package cache)

Created: 202611020117 (Asia/Jakarta). Follows `202611020106-analysis.md`.

## 1. Where the time went

Each step of `RunSongSelect` was timed with temporary log lines (Release build, `--select`):

| Step | Before |
|---|---|
| `LoadSongList` | 0.67 s |
| `UiText::Load` (fonts) | 0.05 s |
| `UiScreen::Load("ui2/20_setup")` | 4.43 s |

`UiScreen::Load` reads hundreds of entries (parts, layouts, clips, textures) from cmp-wrapped `ui2` packages. `Vfs` cached only the last unpacked package, and it had two costs:
- **Copy on every hit:** every read copied the whole unpacked package before walking down to the entry.
- **One package only:** loading switches between `20_setup_en`, `20_setup` and `00_common_en`, so each switch unpacked a package again.

## 2. Change (`src/engine/fs/vfs.{h,cpp}`)

- `Descend` walks a read-only view of the cached package. It copies only the requested entry, plus any nested cmp level it has to unpack. Entry ranges are checked against their archive.
- The cache keeps the 4 most recently used unpacked packages. Unpacked ui2 packages are about 10–30 MB each.

| Measure | Before | After |
|---|---|---|
| `UiScreen::Load("ui2/20_setup")`, Release | 4.43 s | 0.65 s |
| Song select open, Release | 5.2 s | 1.4 s |
| Back to the song select after a live, Debug | 8.7 s | 1.0 s |

All 5 tests pass. `work/m6/loop_d.png` shows the song select back on song 0030 after Esc in its live, as before.

## 3. Open

- `LoadSongList` (0.67 s in Release) is not looked at.
- The cache size (4) is a guess sized for one screen plus its borrowed packages; memory use is not measured.
