## 1. `ANMT` / `ANVS` decoded

Details are in `repository/docs/formats/bmar.md` ("ANMT and ANVS").
- `ANMT` holds per-material channels: colour (type 6, 0–255), transparency (type 4, *Hypothesis*), and type 5 (unknown).
- `ANVS` holds per-node visibility (type 11, step keys).
- No clip animates UVs, so a menu's label-atlas cell is chosen by game code.

`sif_bmar_test` checks clip `uip0004_MenuList00_a004`:
- 4 material and 8 visibility channels;
- the banner colour runs linearly from 0 to 255 between frames 10 and 15;
- `menu_icon00` is hidden from frame 15 (step).

## 2. Layout resolution

These rules come from `uil0001_TopMenu00` and its children:
- **Node names = id + local name.** A node `uip0004_MenuIcon00_00` places the part with id 0004 (`uip0004_MenuList00`). The local name and the `_NN` instance suffix differ per placement. Resolution: the exact entry name first, then the entry with the same `uipNNNN_`/`uilNNNN_` id.
- **Nested layouts:** a node naming a `uil` entry draws that layout at the node.
- **Borrowed parts and layouts:** `common_` → `ui2/00_common[_<lang>]`; `ctgNN_` → the `ui2/NN_*` screen (`ctg03_uil0005_NameSet00` → `03_card`). Inside a borrowed layout, unprefixed names stay in its own package.

Both the top menu and the title resolve fully. The top menu has 16 parts, 12 layouts and 19 clips, including parts from 00_common and 03_card.
