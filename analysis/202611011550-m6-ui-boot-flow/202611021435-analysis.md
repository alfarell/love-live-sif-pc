# M6: controller input, confirmed on hardware

Created: 202611021435 (Asia/Jakarta). Follows `202611021110-analysis.md`.

## 1. First report: "the controller does not work"

- The app detected the pad: an "Xbox 360 Controller" (an XInput device, as DS4Windows or Steam present a DualShock 4), recognised as a gamepad and opened.
- A new test, `tests/unit/input_test.cpp` (`sif_input_test`), attaches an SDL virtual gamepad and presses buttons through `PollEvent`. Menu D-pad and Cross, and live lanes 0 and 8, give the expected key-down and key-up events.
- **Cause:** the user ran the **Release** build (`work/build/release/sif.exe`). It had last been rebuilt before the input code existed. Without `--data`, each build writes its log to `<exe folder>/data/sif.log`, so the Release log showed no input lines.

## 2. Confirmed

After a Release rebuild, the user's log (`work/build/release/data/sif.log`) shows the pad driving every screen:
- top menu: D-pad up and down move between entries, Cross confirms;
- song select;
- two full songs on the live layout: 0010/01 (rank C, 54.26%) and 0320/01 (108 Perfect, 29 Great, 2 Miss, rank A, 89.81%);
- the result screens and the return to the song select.

The live lane layout itself is still a placeholder (not the game's own mapping).

## 3. Side note

Both pad runs had a mean press offset of about −25 ms (early). This may be pad or audio latency, or simply play style. The saved `audio_offset_ms` calibration was made with the keyboard, so a pad calibration may differ. Not investigated.

## 4. Process note

Rebuild both Debug and Release after code changes; the user runs Release.
