# M6 steps 1–2: UI renderer, boot and title screens

Created: 202611011558 (Asia/Jakarta). Follows `202611011550-analysis.md` (U3). Plan: `plan/202611011550-m6-ui-boot-flow/202611011550-plan.md`.

## 1. Result

`sif.exe --title` shows, from the game's own `ui2/01_title_en.pac`:
1. the CRI logo on white;
2. the Square Enix logo;
3. the English notice ("Caution …");
4. the title screen: sky background, game logo, the "Press Any Key" plate pulsing, the copyright.

Any key or pad button on the title starts the live song (stand-in until the top menu exists).

Window captures (`work/m6/`, not committed): `boot_cri.png`, `boot_notice.png`, `title.png`, and `title_to_live.png` (Enter sent to the window; the live song then runs with its camera). The parts sit where the game's layouts put them; nothing is hand-placed.

## 2. What was built

| Part | File | Notes |
|---|---|---|
| UI pipeline | `shaders/ui.frag`, `Renderer::DrawUiMesh` | The mesh vertex shader, straight-alpha blending, no depth, in the 2D overlay pass; a tint uniform for fades |
| Canvas | `UiScreen::CanvasToClip` | 1920 × 1080, y negative downwards, letterboxed into the window |
| Screen loader | `src/engine/ui/ui_screen.{h,cpp}` | Loads every `uip` part (a `SceneModel`) and `uil` layout of a `ui2/<screen>[_<lang>].pac`; `DrawLayout` places parts at the layout's nodes, with an optional alpha per part; `DrawPart` draws one part at a point |
| Models | `SceneModel::DrawUi` | Draws the textured meshes only (text boxes have no texture) |
| Boot and title | `src/app/title_screen.{h,cpp}`, `main.cpp` (`--title`, `--lang`) | The boot stages use layout `uil0001_Advertise00` (the white background part spans the canvas from its corner, so hand-centring it was wrong; the layout places it at (0, 0)) |
| Vfs | `src/engine/fs/vfs.{h,cpp}` | A one-entry cache of the last unpacked cmp-wrapped top-level file. A `ui2` screen is one 12.7 MB cmp file read about 60 times; loading took about 6 s, now about 1 s |

All 5 tests pass.

## 3. Shortcuts (marked in code)

1. Stage lengths (2.5 s per logo, 5 s for the notice), fades (0.4 s) and the "Press Any Key" pulse are guesses. The real ones are in the eboot's title code and the parts' clips and `BTL` timelines, which are not decoded.
2. Title confirm → the live song directly; top menu and song select are next.
3. No sound on these screens (title music and system sounds come from `sys.acb`, not wired).
4. Text boxes (e.g. "Version 1.01" in `ui_text`) are not drawn: fonts are the next step.
5. The name-entry and member-select flow for a new save (`uil0050`–`0052`) is not shown.
