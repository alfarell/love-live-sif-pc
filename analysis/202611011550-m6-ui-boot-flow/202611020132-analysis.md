# M6: live HUD score digits

Created: 202611020132 (Asia/Jakarta). Follows `202611020117-analysis.md`.

## 1. How the HUD score is built

`ui2/90_ingame` has no `ui_number.bin`, so the HUD score does not use number boxes. Instead, the part `uip0004_IngameScore` holds:
- `IngameScorebase` (the "score" plate);
- 7 digit meshes `IngameScore_00` … `_06`, each with its own material `M_IngameScore_0N`.

Every digit mesh maps the same cell: U 0–0.124, V 0–0.5 of `ui_ingame_top_score00` (384 × 96). That texture is a digit grid of 8 columns: 0–7 on the top row, 8–9 below.

By x position, `_00` is the rightmost digit (ones) and `_06` the leftmost. So the game must pick each digit by shifting its material's UVs. (*Hypothesis* on the mechanism; the eboot routine is not traced. The UV range and the grid fit it.)

## 2. Port

In `RunLive` (`src/app/live_screen.cpp`), whenever the score changes, each digit's material is shifted to its cell: U = 0.125 × (d mod 8), V = 0.5 × ⌊d / 8⌋. The score is shown with leading zeros and capped at 9,999,999. This uses `UiScreen::SetMaterialUv`.
