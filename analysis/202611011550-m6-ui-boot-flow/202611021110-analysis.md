# M6: controller input

Created: 202611021110 (Asia/Jakarta). Follows `202611020222-analysis.md`.

## 1. Approach

Every screen polls SDL events itself and switches on keyboard scancodes. Before this change, only the title and result screens also accepted "any pad button".

Instead of adding pad cases to every screen, `src/app/input.{h,cpp}` adds `PollEvent(SDL_Event&)`. It wraps `SDL_PollEvent` and:
- opens a gamepad on `SDL_EVENT_GAMEPAD_ADDED`;
- turns a mapped pad button into a key-down or key-up event with the same timestamp. The live screen judges inputs by the event timestamp, so pad timing goes through the same path as keys.

All screens and the main loop now call `PollEvent`. `SDL_Init` adds `SDL_INIT_GAMEPAD`.

## 2. Layouts

| Layout | Mapping |
|---|---|
| Menu (default) | D-pad = arrows, South/Cross = Space (confirm), East/Circle = Esc (back), Start = Return |
| Live (set by `RunLive` around its loop) | lanes 0–8 = D-pad Left, Up, Right, Down, L1 or R1, West/Square, North/Triangle, East/Circle, South/Cross; Start = Esc |

The live layout is a placeholder (*Hypothesis*, marked as a `shortcut:` in `input.h`). The game's own pad-to-lane table in the eboot is not traced. The calibration screen uses Space, which Cross gives in the Menu layout.
