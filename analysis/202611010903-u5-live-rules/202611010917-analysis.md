# U5: live rules from the eboot, decompiled with Ghidra

Created: 202611010917 (Asia/Jakarta). Follows `202611010903-analysis.md`.

## 1. Tooling

- Ghidra 12.1.4 (already installed by the user, `GHIDRA_INSTALL_DIR`), headless mode. Import with `-loader ElfLoader -loader-imagebase 0`, so Ghidra addresses equal the `llvm-objdump` ones. Auto-analysis took 178 s.
- `analyzeHeadless.bat` fails on paths containing parentheses ("Love Live SIF (PS4)"), and drive E: has no 8.3 short names. The Ghidra project therefore runs in the session scratchpad (local temp), with a copy of the decrypted eboot; nothing leaves the PC.
- New tool: `repository/tools/ghidra/DecompileFunctions.java`, a post-script that writes one `.c` file per requested address.

## 2. Recovered rules (function addresses in `work/elf/eboot.elf`)

### Grading: `0xA0070(windows, dt, is_release, skills)`

dt = now − timing offset − note time. Windows: 8 ints {early Bad, Good, Great, Perfect, late Perfect, Great, Good, Bad}.

| Case | Result |
|---|---|
| dt < −early Bad (press) | ignored (−1) |
| dt < −early Bad (release) | **Bad** |
| \|dt\| < Perfect | Perfect (4) |
| \|dt\| < Great | Great (3) (skill flag 0 can make it Perfect, flag 3 forces Good) |
| \|dt\| < Good | Good (2) (skill flag 0 can make it Great) |
| otherwise, up to and including the Bad bound | Bad (1) |
| dt > late Bad | Miss (0) |

Inner bounds are strict: exactly 40 ms is Great. Group 0 is used for presses (`0x9FCF0`), group 1 (at judge +0xC8) for hold releases (`0x9FF80`): the release *Hypothesis* is confirmed.

### Recording: `0x9ECC0(note, ctx, time, grade, raw grade, start_hold)`

- A hold enters the held state only if its press grade is better than Bad (`start_hold` set in `0x9FCF0` when grade > 1). A Bad press ends the hold with no release judgement.
- A note that times out (`0x9FDF0`) gets a single Miss, holds included.
- While held, a listener callback fires once per tick, up to `round(hold length / tick length)` ticks (note +0x68). Tick length = `song-context float (+0x130) × 1000` ms. A Perfect or Great release awards the remaining ticks. The source of the +0x130 float is not traced.

### Combo: `0xAA3B0` (called per judgement)

- Perfect, Great: combo + 1, max combo updated.
- Good: combo + 1 only with skill flag 1 or 0x26 ("combo softening" skills), otherwise break.
- Bad, Miss: combo = 0, break counter + 1.

### Score: `0xAA520` (per judgement), `0xA94F0` (maximum score)

- points = `round(combo_multiplier × note_type_multiplier × weight[grade] × skill_multiplier × 100)`, Miss adds nothing, total capped at 9,999,999.
- `s_CommonParam`: weights at +0xC0…+0xCC = Bad 0.1, Good 0.2, Great 0.7, Perfect 1.0; base +0xB4 = 100; note-type multipliers +0x118/+0x11C (1.0); combo multiplier table +0xD0 (9 floats: 1.0, 1.5, 2.0, 2.5, 3.0, …) indexed by a level field (+0x14 of another object, clamped 0–8; source not traced).
- Hold ticks score `combo_multiplier × 1.0 × 10` (base +0xB8 = 10).
- `0xA94F0` sums the maximum score over all notes and ticks. It counts judgements as notes + holds (121 for song 0340 Easy), plus ticks.

### Rank: `0xAAC50`, `0xA9EC0`, `0xAADB0`

clear rate = score / max score (+1e−5) against `s_CommonParam` +0x138…+0x14C = 0.45, 0.65, 0.825, 0.925, 1.025, 1.2 → seven ranks (D … SSS, *Hypothesis* on the letters). `0xAADB0` copies the result into the save data.

### Check against the shadPS4 result screens

The formula is right in size; the game is slightly higher, consistent with the untraced combo multiplier and hold ticks.

## 3. Applied in the port (`repository/src/game/live/judge.cpp`, tests in `live_test.cpp`)

- Strict inner window bounds, inclusive Bad bound.
- Early release → Bad; a Bad hold press ends the hold; an unpressed hold is one Miss.
- Score = game points (100/70/20/10), capped at 9,999,999; combo multiplier fixed at 1.0 and hold ticks not scored (`shortcut:` comment).
- Combo rule unchanged; now confirmed.

## 4. Still open (U5 remainder)

1. Combo-multiplier level (+0x14) and the tick-length float (+0x130): their writers.
2. The result screen's judgement total (128/132 vs 121): likely ticks are counted, to be confirmed against the tick rule.
3. Input-device offset (`s_CalibrationData` 16/32 ms): which device is which. Not applied in the port, which has its own calibration.
4. Skills (flags 0, 1, 3, 0x26 and the +20 ms window groups): not implemented.
