**Method:** Ghidra decompiles (the earlier session's scratchpad `gh`) and `work/eboot.asm`. `S` = the main save (`FUN_00071de0`).

## 1. The mission tables and rows (done)

- **The loader** (`FUN_001c26b0`): four row tables at `0xE39990 + t × 0x10`, read by `FUN_001c2850` (count) and `FUN_001c2870(t, i)` (row). The conditions are at `0xE399D0` (`FUN_001c2970(kind)`).
- **A row (28 bytes):**

  | Offset | Content |
  |---|---|
  | +0 | id |
  | +4 | the condition kind (byte) |
  | **+5** | **the show rule** (byte; the port's "code high byte") |
  | +8 | p1 |
  | +0xC | p2 |
  | +0x10 | the reward |

- **A condition** (72 bytes) has two type bytes:
  - `+0x41` says what p1 is, and `+0x42` what p2 is;
  - type 1 = the count needed (`FUN_001c7ab0`: need = p1 if `+0x41` is 1, else p2 if `+0x42` is 1, else 1);
  - type 2 = a group, 3 = a member, 4 = a song, 5 = a costume.

## 2. Which rows the Task List shows (done)

**`FUN_001c6db0(table, group)`** builds a tab's list. It keeps the rows that pass two checks.

**`FUN_001c6bd0(row, member, group)`, the filter.** For each parameter by its type:

| Type | The row is kept when |
|---|---|
| 2 (group) | p == the current member's group (`FUN_0001ead0`: 0 µ's, 1 Aqours and Saint Snow) |
| 3 (member) | p == the current member |
| 4 (song) | the song's group (`s_music_datas +0x10`, 1-2 → Aqours) matches the member's group |
| 5 (costume) | the member can wear the costume (its group mask `+0x54`, `FUN_0001eb50`) |

**So the game shows:**
- the current mode's group rows;
- only the current member's member rows;
- only her group's songs;
- only costumes she can wear.

**`FUN_001c6ea0(row)`, the show rule** (row byte `+5`):

| Rule | Shown when |
|---|---|
| 0 | always; once claimed it is hidden **if the next row (id + 1) is a following step** (its rule is 1) |
| 1 | a step of a series: shown only after the previous row (id − 1) is claimed; once claimed, as rule 0 |
| 2 | the song is owned (`FUN_001efa70`, the add-on check) |
| 3 | the costume is owned (`FUN_001efc40`; costume 217 is checked as 117) |

**So a series** (e.g. "play 10 / 30 / 50 times") shows **one step at a time.** The port lists every step.

**Saved state:**
- `S + 0x55938`: a 5000-bit "completed" set;
- `S + 0x55BA9`: a "claimed" set;
- `S + 0x55E1A`: a third set (*hypothesis:* "seen" or "new");
- progress have/need per id in a table (`+0x70`/`+0x74` of the tracker object).
