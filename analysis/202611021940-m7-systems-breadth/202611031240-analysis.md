# M7 step 4: `message.pac` decoded

Created: 202611031240 (Asia/Jakarta). Follows `202611031159-analysis.md`. Resumes the paused work of `analysis/202611011550-m6-ui-boot-flow/202611021703-analysis.md`. Spec: `repository/docs/formats/message.md`.

## 1. What was wrong before

The pause note had three readings that turned out wrong:
1. **"English uses another encoding."** It does not; it is plain ASCII. The texts only looked broken because they were cut.
2. **"Entries are framed differently."** True, and now understood. Each block is u32 size, u32 `4`, content. The generic ARC reader takes the `4` for the header length, starts 4 bytes early and ends 4 bytes short.
3. **"message.pac starts with u32 4."** That was the extractor's output files. The file itself is a plain ARC of the 4 language packages.

## 2. What a table is

- **Each entry is one message**, numbered by its index (816 per language).
- Its rows are its **characters**: "New Player" has 10 rows, "Unregistered text" 17, "Profile Card Support" 20. Each row points to an 8-byte per-character record (`df 07 0a ff`; style or colour, *Hypothesis*).
- The text itself is a NUL-terminated UTF-8 string at the offset in the header, with `\n` and `\uXXXX` escapes.
- The earlier "many rows point to the same place" was these character rows.

How it was found:
1. The block sizes were compared with the real gaps between blocks.
2. The tables were re-read from block + 8.
3. The row counts were matched to the character counts of the strings.
