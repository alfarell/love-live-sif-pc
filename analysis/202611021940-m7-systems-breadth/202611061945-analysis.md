# M7 step 4 follow-up: messages on screens, fallback, format closed

Created: 202611061945 (Asia/Jakarta). Follows `202611031240-analysis.md`. Spec: `repository/docs/formats/message.md`.

## 1. What changed

- `sif::Messages` now reads Japanese and the selected language together. `Get(id)` returns the selected text, and falls back to Japanese when it is empty or ends in `Not Defined` (`English`, `Eng Music`, `Eng UI`, `Schinese`, `SC Music`, `SC UI`, `Tchinese`, `TC Music`, `TC UI`).
- `Messages::Japanese(id)` always returns the Japanese text. `Messages::Format(id)` exposes the header counts and per-row style records.
- `sif::Localizer` (`src/game/text/localizer.{h,cpp}`) builds `Japanese text -> message id` and resolves a UI default. `LocalizeScreen` applies it to a loaded `UiScreen`.
- `UiScreen::LocalizeTexts(std::function<bool(std::string_view, std::string&)>)` keeps the engine independent of `game/text`.
- Title, top menu, song select, result and the live HUD call `LocalizeScreen` after `Load`. Options uses the localizer directly for the title plate and row labels (`706/707`, `711`, `712`, `718`).

Why exact-text matching: `ui_text.bin` keeps the Japanese defaults even in `_en`/`_cn`/`_tw` packages, and message ids are stable across languages. Matching the Japanese default to the Japanese message table is enough; no eboot trace is needed for boxes that keep a default.

Limits: defaults with extra punctuation (`作詞:` vs message `作詞`) are not matched, and values the port fills itself (dates, counts, row labels) keep their own text or use an explicit id.

## 2. Format closed

- Header counts are `(style rows, text characters, UTF-8 bytes)`. Line breaks count as characters but not as rows: Japanese 814 is `(16, 17, 49)`, English 814 `(20, 20, 20)`.
- Rows are `(u16 flags, u16 offset)`, the offset relative to the row.
  - `0` shared/default record (or no record when the row points at the text offset);
  - `1` one owned 8-byte record;
  - `2` a 16-byte record pair.
- A record is `(u32 type, u32 value)`:
  - type 0: colour (`df070aff`, `333333ff`, `1d1c1dff`, `00000000`), *Hypothesis* ARGB;
  - type 1: size, 9/16/24; Japanese 613 `Lv.%d` gives 16 for `Lv.` and 24 for `%d`, so it tracks font size;
  - type 2: only in kind-1 fragments, value 0.
- Kind 1 is 21 single-symbol messages in Japanese (`■`, `×`, `歌`, `凛`, …). They are structurally normal (one row, a flag-2 pair, one-character text) and the reader handles them.
- Message 815 is complete: `(NPC Profile Card)` in all four languages. The earlier `(NPC Profile Ca` was the extractor cutting 4 bytes, not the data.
