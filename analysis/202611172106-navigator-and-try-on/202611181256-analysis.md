Date: 2026-11-18 12:56 (Asia/Jakarta). Step N1 of `plan/202611172106-m13-navigator-and-try-on/202611172106-plan.md`. Follows the survey (`202611172106-analysis.md`).

**Method:**

- `work/eboot.asm` for cross-references;
- `work/m13/char_params.py`, which reads `character_params.bin` from the dump in memory.

String addresses are file offsets − 0x4000. `G` below is the game's global data block (`*0xE04E20`), and `S` = `G + 0x8F720`, the main save (`FUN_00071de0`).

## 1. Member and group in the save (done)

| Where | Content | Code |
|---|---|---|
| `S + 0x48` | **Group mode**: 0 µ's, 1 Aqours (L2) | read by `FUN_000730a0`; set by `FUN_00187ff0` and `FUN_00119ad0` |
| `S + 0x50 + g × 0x1A0` | **The chosen member of group `g`** (R2). A new save has 1 (Honoka) for µ's and 11 (Chika) for Aqours | init `FUN_00070840` (`0x70EC1`, `0x70ED9`); set `FUN_000741e0` |
| `S + 0x58 + g × 0x1A0 …` | the group's profile card in use (MyProca is kept per group) | copy `FUN_000749c0` |
| `S + 0x540` | the previous group, kept when a member of the other group is chosen | `FUN_00119ad0` |
| `G + 0x46507C` | **temporary member** (message 591), not saved; cleared on leaving | set `FUN_00119ad0(member, temporary=1)` |

- **Group of a member:** `FUN_0001e460(m)` gives 0 for 1-9, 1 for 11-19 and 2 for 21-22 (Saint Snow). The save's group mode only toggles 0/1. A Saint Snow member is chosen from the Aqours side; *hypothesis*, check in N2.
- **The current member** (`FUN_000715b0`): the temporary member if one is set; else the member of the current group.
- **A live request** (`G + 0x4643A0`, built in `FUN_00185ee0` and `FUN_00185ba0`):
  - `+0xE8`: the member;
  - `+0xEC`: her costume;
  - `+0xF0`: her special-colour flag;
  - `+0xA78`: the group.

  Lives, skill cards and photos use this member. The port uses `--member` or Honoka.

## 2. Each member's costume and special colour (done)

**Per-member record:** `S + 0x658 + i × 0xDC`. `i` is the member index from the table at `0x5E3690`: members 1-9, 11-19 and 21-22 → 0-19.

| Offset | Content |
|---|---|
| +0x00 | the **member card** she wears (the costume is the card's `+0x14 % 1000`, `FUN_000696b0`) |
| +0xA8 | **special colour** (1 byte, `FUN_00069740`) |

**"Change Clothes"** (`FUN_000694d0(member, costume, colour)`):
1. It looks for the member's card for that costume, type 2 first, then type 1. The type is the card table's `+0x08`.
2. It keeps the first one the player owns.
3. It stores the card and the colour flag.
4. It clears the costume's "new" mark (`S + 0x560CC`, 0x2C-byte rows).

So **the colour is chosen together with the costume and kept per member**. The live passes it on (`+0xF0`).

**The model path** (`FUN_0001bda0(kind, member, costume, variant)`):
- kind 0: the body `chr/c%02d/c%02d.pac`;
- kind 2, variant 0: the costume `chr/c%02d/d%03d/d%03d.pac`;
- kind 2, variant > 0: the costume `chr/c%02d/d%03d/d%03d_v%d.pac`;
- kind 1: a live's own costume `live/%04d/c%02d_%04d.pac`;
- costume 25 is loaded as `d000`.

**Default costume per group** (`0x5E3538`): µ's 0, Aqours 105, Saint Snow 200.

**Port effect:**
- The port's `wear` line (costume per member) matches the game's idea.
- Add the colour flag.
- In lives, load `d%03d_v1.pac` when it is set.

## 3. The navigator's idle loop (done)

**Data:** `common/common.pac/character_common.pac/character_params.bin`.

**`s_idle_animation_datas`:** 6 rows of 16 bytes: the motion number, then one weight per group (µ's, Aqours, Saint Snow).

| Motion | µ's | Aqours | Saint Snow |
|---|---|---|---|
| 10 (`010_idle`) | 100 | 100 | 100 |
| 11 | 100 | 0 | 100 |
| 12-15 | 100 | 0 | 0 |

**`s_common_param`:** 120, 180, 60, 300, 120, 0.1, 10, 100. Fields 0-2 are used below; the others are not traced (field 5 goes to a shader parameter, `FUN_0002f0a0`).

**The loop** (`FUN_00015970`, one per 3D member in a menu; timer `FUN_00015ae0`; pick `FUN_0001dee0`):
1. **Stand:** play motion **1** (`001_stand`) with flag `0x11` (*hypothesis:* loop) after an idle ends.
2. **Wait:** 120 + r × 180 frames, where r = xorshift128 >> 16 × 1/65536. That is 2-5 s at 60 fps.
3. **Pick an idle:** weighted by the member's group column, with r × (sum of weights + 1). The default is 10.
4. **Play it:** flag `0x10` (*hypothesis:* once), blend 60 (`s_common_param` field 2; *hypothesis:* frames).
5. Back to step 1.

- **Random number:** a xorshift128 of its own, seeded from the constants at `0x5E35C0` / `0x5E3260`. It is not the game's other generators.
- **Motion names:** a motion number *n* is the file `mot_%02d_<name>_%03d_*` with that number (`010_idle`, `001_stand`). The number is read from the file name; the eboot lookup by number is not traced.
- **Port effect:** this loop is small and fully known, so N4 can build it as the game does.
