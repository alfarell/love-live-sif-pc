## 2. Input

### Timing

- **Events are drained once per rendered frame:** `PumpEvents` (`src/main.cpp:5063`) loops `SDL_PollEvent` (`:5072`, checked) and passes each event to ImGui and `InputDevice::ProcessEvent` (`:5078-5080`). The call site is `:5887`.
- `ProcessEvent` only keeps accumulators and edge latches (`src/engine/platform/input.cpp:635-744`), so a press and release inside one frame is not lost (`event_raw |= RawFromButton`, `:696`).
- **State is polled once per frame:** `InputDevice::Poll` (`input.cpp:784`) is called at `main.cpp:6140` (checked). It reads held state with `SDL_GetKeyboardState`, `SDL_GetMouseState`, `SDL_GetGamepadButton/Axis` (`input.cpp:613-627`, `:789-794`, `:908-910`).
- **Ticks reuse the frame's sample:** the result is merged into `pending_input` (`main.cpp:6190-6200`; `MergeFrameButtons`, `input.cpp:380`). Each fixed 60 Hz tick copies it (`main.cpp:6405`). Deltas and edges reach only the first tick of the frame; held state repeats (`:6481-6489`).
- **SDL event timestamps are not used for input.** The only use is the gyro sensor timestamp, for integration (`input.cpp:719-722`, checked).
- **No input-to-photon latency measurement.** The only latency tooling is NVIDIA Reflex/PCL markers (`render/upscale/streamline.cpp:345-362`; `render/d3d12/backend/d3d12_device_impl.cpp:821-822`, `:882`) and an opt-in tick CSV (`PT_TICK_CSV`, `main.cpp:6416`, `:6476-6479`).

### Pad model (mapping layer)

- **PS4-style raw bits:** `PadRaw` (`input.h:21-38`), Square = bit 0 through Right = bit 15.
- **SDL mapping:** `RawFromButton` (`input.cpp:155-172`) maps SOUTH/EAST/WEST/NORTH to Cross/Circle/Square/Triangle, plus sticks, shoulders, Start and D-pad.
  - L2/R2 count as pressed when the axis is above 0 (`:620-625`).
  - Touchpad click is split into halves by x position (`:182-194`, `:610`).
  - With several pads, their bits are ORed (`:886-921`).
- **Keyboard and mouse** drive the same raw bits through `KeyBinding` (`:810-825`). Mouse motion becomes `mouse_look` (`:867-869`).
- **P.T. layer on top:** `PadButton` / `PlayerButtonsFromRaw` with `kPlayerRawBits` (`input.h:40-53`, `input.cpp:26`, `:370-378`), the voice chord L2+R2 (`:888-890`) and the gouge button (`:892-900`).
- **Rumble:** `SDL_RumbleGamepad` / `SDL_RumbleGamepadTriggers`. Values are scaled ×257, sent for 1000 ms and refreshed every 400 ms (`input.cpp:24-25`, `:1037-1080`). Trigger rumble is off by default (`input.h:146`; `controller_feedback.cpp:10-16`).

## 4. Frame pacing

- **Vsync** is on by default; `--no-vsync` turns it off (`main.cpp:268`, `:350`, `:566`).
  - Vulkan: FIFO when vsync is on; otherwise IMMEDIATE, then MAILBOX, then FIFO (`render/vk_context.cpp:815-819`, checked).
  - D3D12: `Present(vsync ? 1 : 0)`, with tearing allowed when vsync is off (`render/d3d12/present/dxgi_presenter.cpp:186-187`).
- **CPU frame limiter** (`main.cpp:7515-7559`): `fps_limit` 0/30/…/360 (`:2929`); 60 fps in menus or when paused (`:7516-7522`); `SDL_DelayPrecise` to a fixed deadline, which resets when more than one period late (`:7543-7555`).
- **Reflex:** under DLSS frame generation, the cap moves to `streamline::SetFrameLimit` with Reflex low-latency mode, and `slReflexSleep` runs at frame start (`main.cpp:7525-7542`; `render/renderer.cpp:593`; `render/upscale/streamline.cpp:356`, `:409-419`).
  - Inference (subagent): Reflex samples input just in time. The CPU limiter sleeps after rendering, so input can be up to one extra frame old.

### Wwise behaviour without the runtime

- **Command queue:** API calls push commands under a mutex; the audio callback drains them at the start of each `Render` (`sound_engine.cpp:3655-3662`).
- **Actions** (`ExecuteAction`, `:998-1055`): Play, Stop, Pause/Resume, SetAkProp (volume/pitch/LPF/bus volume), SetState, SetSwitch, Set/Reset GameParameter, Break, Seek. Others log "not supported" (`:1050-1053`). Delayed actions go to a pending queue.
- **Nodes** (`PlayNode`, `:1070-1095`): Sound, random/sequence containers (weights, shuffle, avoid-repeat, continuous, step), Switch, Layer (RTPC crossfades), MusicRanSeq/MusicSegment, Feedback (rumble), DialogueEvent trees. `MusicSwitchCntr` is parsed but not played (`:1090-1092`).
- **Sources** (`:1386-1412`): PCM, ADPCM, Vorbis, External (demo streams), Silence, Tone.
- **States, switches, RTPCs:** with curves and transition ramps (`wwise_bank.h:83-106`, `:614-619`). Ramps are quantised to `kEbootFrame = 1024` samples (`sound_engine.cpp:29`, checked; `:262-279`), emulating the PS4 Wwise update tick (Inference).
- **Buses:** tree with gains, ducking (`:2589`) and per-bus state/RTPC.
- **Effects:** RoomVerb, MatrixReverb, StereoDelay, PeakLimiter (`dsp.cpp:1267-1270`); aux sends; voice limits and virtual voices.
- **3D:** attenuation curves (dry, aux, LPF, spread), cone, obstruction/occlusion, path automation, panning over a 7-speaker layout (`:38-44`, `:2713-2799`).
- **HDR bus** is parsed but appears unused (Inference).

### Decoding, mixing, clocks

- **Codecs:** PCM16, Wwise IMA ADPCM, Wwise Vorbis (matches vgmstream within 1 LSB, `docs/formats/audio.md:132-138`).
- **Memory:** all media in memory, no disk streaming (`audio.md:3-4`, `sound_package.cpp:213`). Decoding is incremental per voice.
- **Resampling:** linear per voice (16.16 fixed point) to 48 kHz (`sound_engine.cpp:3140-3161`, `:2862`). All P.T. media is 48 kHz (`audio.md:120`).
- **Mixer:** 48 kHz (`dsp.h:13`, checked), internal block `kBlockFrames = 256` (`sound_engine.h:29`, checked). It runs **in the SDL3 audio-stream callback**, not on a separate mixer thread: `SDL_SetAudioStreamGetCallback` (`audio_engine.cpp:152`, checked), render the requested bytes, `SDL_PutAudioStreamData` (`:303`, checked).
- **Layouts:** stereo, 5.1, 7.1; Wwise→SDL channel order; 5.1 folds back+side at −3 dB (`channel_layout.h:9-47`); LFE silent (`docs/audio-surround.md:20`).
- **Latency:** no device buffer-size hint is set (`grep SDL_HINT_AUDIO_DEVICE_SAMPLE_FRAMES` finds nothing in `src`, checked), so latency is the SDL/WASAPI default. No latency figures are documented.
- **Audio clock:** `rendered_frames_` is an atomic counter advanced after every render unless paused (`sound_engine.cpp:3669-3671`, checked), exposed as `RenderedFrames()`.
  - Cutscenes slave their frame counter to it, with resync over a threshold and smoothing below it (`game/demo_system.cpp:896-911`). Voice timing also uses it (`main.cpp:4491`, `:4570`).
  - It counts frames **rendered**, not frames **played**: no device delay is subtracted (subagent).
- **Output:**
  - endpoint selection with fallback; channel probe 8 → 6 → 2; hot-plug polled once per second (`audio_engine.cpp:36-269`);
  - Windows `ISpatialAudioClient` 7.1 bed (`spatial_output.cpp:28-31`, `:146-208`);
  - controller speaker routes, with data dropped above 100 ms of queue (`controller_speaker.cpp:706`, `:724`).

### Class

### Frame flow

1. **`renderer.BeginFrame()`** (`main.cpp:7228-7299`): Vulkan waits for the frame fence, reaps uploads and acquires a swapchain image (`renderer.cpp:568-676`). D3D12 calls `gpu_->BeginFrame` (`:1952`).
2. **`SceneRenderer::Render`** (`scene_frame.cpp:2684-3071`):
   1. frame data upload;
   2. shadows (which first build the RT acceleration structures);
   3. mirror view;
   4. main view (`RecordView`, `:2442-2639`): gbuffer → velocity → SSAO / RT AO → RT trace → deferred lighting → subsurface → path-traced indirect → compose + forward → VFX;
   5. reflections → upscale (DLSS/FSR/XeSS);
   6. post: bloom, DoF, motion blur, tonemap, FXAA (`scene_renderer.h:553-576`).
3. **`renderer.EndFrame()`**: composite → UI and ImGui → `vkQueueSubmit2` → present (`renderer.cpp:837-1056`).

- **Sync:** `kFramesInFlight = 2` (`renderer.h:114`, checked). Binary semaphores and a fence per frame; timeline semaphores only for upscaler/frame-generation interop (`renderer.cpp:1009-1087`).
- **Pipeline cache:** disk `VkPipelineCache` keyed by vendor/device/driver UUID, 64 MB cap, atomic background writes (`pipeline_cache_store.h:18-75`), plus a warmup thread pool (`pipeline_warmup.h:13-36`). D3D12 has no PSO disk cache.
- **Threading:** all command recording is on the **main thread**, one command list per frame (confirms Part 5, Open question 2). Workers only do pipeline warmup, cache saving and texture decode-ahead (`pipeline_warmup.h:29`, `pipeline_cache_runtime.cpp:143`, `texture_manager.cpp:580`).

### Shaders and build path

- **Vulkan:** `glslc --target-env=vulkan1.3` at build time (`CMakeLists.txt:226-243`, Part 1). At run time `LoadShaderModule` reads `<exe>/shaders/<name>.spv`, falling back to `PT_SHADER_DIR` (`vk.cpp:93-113`, `core/resource_path.cpp:30-37`, `CMakeLists.txt:257`).
- **Bindless:** `set=0` holds `textures[]` and `cube_textures[]` (`shaders/common.glsl:56-57`); D3D12 uses a separate sampler (`shaders/bindless.glsl:1-11`). Limits 8192 textures, 64 cubes (`texture_manager.h:51`, `:58`, checked).
- **D3D12:** `glslc -DPT_D3D12` → `spirv-opt` → SPIRV-Cross (`tools/dx12/spirv_to_hlsl`) → HLSL SM 6.6 → DXC → `.dxil` plus a `.dxil.json` resource manifest checked against the root signature (`cmake/D3D12Shaders.cmake:1-5`, `:55-82`).
- **No hot reload.** **No PS4 shader binary is used at run time:** only `.spv`/`.dxil` are loaded, and grep finds no GCN/PM4/GNM/`.sb` handling in `src/` (subagent; consistent with Part 1, section 5).

### Textures and models

- **Upload:** `TextureManager::Create` uses staging buffers, barriers and `SubmitDeferred` with a 256 MB in-flight limit, then writes a bindless descriptor (`texture_manager.cpp:339-479`, `vk_context.h:184`). Formats: BC1-BC7 + a few uncompressed (`gpu_enums.h:30-45`).
- **Source:** Fox `.ftex` from QAR (`LoadFox`, `:481-555`), PNG mod overrides.
- **No detiling** (data is already linear BC, `docs/formats/textures.md:196-199`, Part 1).
- **No mip streaming:** whole textures upload at once, and the largest mips are dropped under VRAM pressure (`:350-378`). Async decode-ahead.
- **`ModelCache`** (`model_cache.h:33-88`): FMDL → `GpuMesh` with a fixed 9-attribute vertex (`mesh.h:16-26`), stage refcounts. Contains P.T. hacks (`LisaHairShadow`, `model_cache.cpp:22-23`; `fox_3ddf_hair`, `:295`).

## 7. What SIF could reuse, by approach

| Subsystem | A: rewrite (pt-pc style) | B/C: emulation / HLE |
|---|---|---|
| Device layer | `gpu::Device` + `vk_context` + optional D3D12, unchanged | `vk_context` (device, queue, VMA, swapchain, HDR, pipeline-cache store) is a useful base. **`gpu::Device` does not fit**: pipelines are named shader files (`gpu_resources.h:240`), fixed blend enum and vertex model, no GPU-address/tiling/aliasing model, single queue (subagent Inference). An emulator needs pipelines keyed by GPU register state, guest-memory-backed resources and detiling, as shadPS4's Vulkan layer has |
| Frame loop / present | `Renderer` shell, vsync, frame cap | Present and swapchain code; the game drives flips itself (`sceVideoOut*`, Part 3 follow-up) |
| Shaders | Toolchain reusable; **SIF's ~27k GCN shaders (Part 3) would need hand-written replacements**, as pt-pc did for ~120 | Needs a GCN → SPIR-V recompiler (shadPS4 has one). pt-pc's `gcn.py` is only a disassembler |
| Textures | Bindless upload core | Needs PS4 tiling/detiling. SIF textures inside `.pac` are not yet checked (Open questions) |
| Audio | Output layer only; needs a CRI ADX2 runtime: HCA decoder, AWB/ACB parsing, cue logic | **Simplest:** the game's own CRI library decodes and mixes and calls `sceAudioOutOutput` (Part 3: no Ajm/Ngs2). pt-pc's `AudioOutput` with a ring buffer filled by the guest is enough, plus `channel_layout.h` and endpoint selection |
| Video | Nothing in pt-pc; needs a USM (Sofdec2) decoder | The game's own CRI Mana decodes on the CPU (Part 3); only texture upload is needed |
| Input | Raw PS4-pad layer | Same layer feeding `scePadRead` |

### Rhythm-game timing needs (SIF)

pt-pc's design is fine for P.T., but a rhythm game needs more:

1. **Audio-clock note timing.** pt-pc's `RenderedFrames()` counts frames *rendered*, not *played* (section 5). A port must add the device output latency (WASAPI/SDL stream latency) or a user calibration offset. In emulation, the HLE `sceAudioOut` must block and pace like the console (per-port grain) and report positions consistent with real playback. Otherwise the game's CRI clock drifts from what the player hears.
2. **Input timestamps.** pt-pc polls input once per frame and feeds 60 Hz ticks (section 2), with no SDL event timestamps. For judging taps, a port should timestamp every input event (SDL3 event `timestamp`, in ns) and map it onto the audio timebase. In emulation the game polls `scePadRead` itself, so the HLE should poll at a high rate or return the latest state with low delay.
3. **Small, configurable audio buffer.** pt-pc sets no device buffer-size hint (section 5). SIF should use a small buffer (for example `SDL_HINT_AUDIO_DEVICE_SAMPLE_FRAMES`) and document the latency. Hypothesis: on the PS4, `sceAudioOut` uses fixed grains of 256/512/1024 samples.
4. **Present latency.** Vsync FIFO plus a CPU limiter that sleeps after rendering adds up to a frame of input age (section 4). Offer low-latency present modes (MAILBOX/IMMEDIATE, tearing) and a calibration screen.
5. **Video sync.** SIF's song videos (`movie/music/preview_music_*.usm`, `monitor_*.usm`, Part 2) must stay in sync with music. In emulation the game handles this itself if the clocks are right.
