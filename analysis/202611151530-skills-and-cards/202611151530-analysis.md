# M11 survey: skill cards and member cards

Date: 2026-11-15 15:30 (Asia/Jakarta). The user chose "Skills and cards" as the next work after M10. This survey reads the data tables, the game's texts and the eboot's strings. Nothing was run in shadPS4 yet.

**Helpers** (`work/m11/`, all read the dump in memory, nothing extracted):
- `blbn.py`: lists a BLBN table's symbols or dumps records;
- `skill_types.py`, `skill_peek.py`: decode the skill cards;
- `member_cards.py`: decodes the member cards;
- `mission_cards.py`: matches task rewards against card ids;
- `msg_grep.py`: greps the English texts.

## Member cards

**Record:** 7 × i32 fields:

| Field | Content |
|---|---|
| +0x00 | card id = costume key × 10 + picture (`10011`, `10010`) |
| +0x04 | index 1-1038 |
| +0x08 | 2 or 1, the picture kind (519 each) |
| +0x0C | costume key = member × 1000 + costume number (`1001`) |
| +0x10 | member 1-22 |
| +0x14 | costume number |
| +0x18 | 0, or 2 on 20 cards |

- **One card per member and costume,** in two pictures. These are the `mbc_` textures of `ui/ui_member_card_thumbnail*.pac` that the M7 song select hid (`card_center00_M`, `card_R00_M`).
- **Hypothesis:** a member card is owned once its costume is owned. No table gives member cards as rewards (`mission_cards.py`: 0 matches), so they are not dropped or given on their own.
- **Not decoded:** the meaning of picture kind 1 and 2, and of the value 2 at +0x18.

## Skill cards

**Record:** 32 × i32 fields:

| Field | Content |
|---|---|
| +0x00 | card id = member × 10000 + series × 1000 + type (`11000` … `223027`) |
| +0x04 | skill id 10000-10408 |
| +0x08 | member 1-22 |
| +0x10 | **effect kind** (table below) |
| +0x18 … +0x58 | 9 string offsets: the name (JP, EN, CN, TW), the description (same order), the picture name (`skc_1100_chara`) |
| +0x64, +0x68 | 58, 58 (not decoded) |
| +0x6C | 10, or 1 for skills that do not change with level |
| +0x70, +0x78 | not decoded (`15184`; `2000`) |

**Series** (the thousands digit of the id):
- 1 = the live skills, 101 cards;
- 2 = material and booster skills, 157 cards;
- 3 = friendship, camera and shoutout skills, 157 cards.

**Level record:** f32 value, i32 a, i32 b, 0, then 4 string offsets (the level text in JP, EN, CN, TW). There are 11 rows; row 0 equals row 1, so levels are 1-10.

Examples:
- **Judge Support:** value 5 → 14 s, a 82 → 100, b 50. Text: "Enhances timing window for 5 seconds".
- **Drop Support:** value 2, a 10 → 30, b 25. Text: "A 10% chance of getting a Wai-Wai! Booster…". So a is a chance in %.
- **Hypothesis:** for the timed live skills, a is the activation chance in % and b is how often they are tried (every 50 notes?). Not proven; the eboot decides (plan step S1).

**Judge code:** the U5 analysis found skill flags 0, 1, 3 and 0x26 in the judge (`0xA0070`, `202611010917-analysis.md`). They are these kinds:
- 0 `extendEvaluation`;
- 1 `extendCombo`;
- 0x26 = 38 `judgeSupportPlus`;
- 3 `boostVsReductEvaluation` (no card).

The +20 ms window groups 2-3 of `s_EvaluateRangeDatas` (`docs/formats/blbn.md`) are the likely `extendEvaluation` windows.

## How the game uses them (its own texts, `msg_grep.py`)

- "Select up to three Skill Cards to set." "Skill Card Selection", "Skill Card in Use", "Skill not set."
- "Set Skill Cards to improve your score during Play Live Show mode, or to obtain costume materials easier."
- "No Skill Card Play Live Show and complete tasks to get Skill Card!"
- "Birthday Events occur when a member's birthday is approaching. Participate in Birthday Events to get special Skill Cards!"
- "[Automatic activation]"

**Save fields** (eboot strings `0x5FB907`): `playerInfo[%d].skillCards_[%d].cardIdx_` and `.level_`. So each player keeps a list of set skill cards, each with a level.

**Task rewards:** reward type 1, until now a guess, is a **skill card**. 92 member-task rows (`mission_recommended`) give one, and all 92 ids are skill card ids. The other task tables give none.

**Screens:**
- **Collection → Skill Card:** top-menu entry 17, `uil0012_GallerySkillWin00`, `uip0008_SkillWin00`, `uip0020_SkillCard00`; `40_collection` also has `uil0065_ProfileskillGroup00` for the profile card.
- **Setting the three cards:** `ui2/80_skill_card.pac` (`uil0002_SkillSet00_s`, `uip0001_SkillList00`, `uip0002_SkillList01`, `uip0005_SkillParts00_S`). Where it opens (live setup or the collection) is not known yet.
- **During the live:** skill effects (`skill_effect00`-`02`, `s_skillEffectShower`, `s_skillEffectFrame`) and skill voices (`s_skillVoiceCues`, 100 cue ids; `s_skillVoiceCallNum` = 30).

## Not known yet

1. **When a live skill fires:** the chance, how often it is tried, how long it lasts, and whether "[Automatic activation]" skills always fire.
2. **What each live effect does in numbers:** the windows, the combo rule, Starting Combo Support's length, the finale icon count.
3. **How skill cards are obtained after a live:** the drop rate, which member's cards drop, and how a duplicate raises the level.
4. **Whether skills also act in Play Live Show (AC).** The texts name only Play Live Show.
5. **Where the three-card set screen opens.**
6. **Member cards:** whether they come with the costume, and their screens (Collection → Member Card, the song select pictures).

Items 1-3 need the eboot (the readers of `s_skill_card_level_params`, the judge flags, the result-screen drops). Items 4-6 need a shadPS4 run with a save that has skill cards: a new save has none, so the run has to earn one through a task or a drop first.
