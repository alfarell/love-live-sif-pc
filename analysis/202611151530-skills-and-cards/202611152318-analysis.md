## Eboot (new in S6)

The Ghidra decompiles are in the session scratchpad and not committed: `FUN_000a68d0` (the result), `FUN_001f2ab0` (the reward draw), `FUN_000679a0` (the material drop), and `FUN_0001e9f0`/`FUN_0001ea10` (member index tables).

### The skill card drop (`FUN_000a68d0` → `FUN_001f2ab0(…, 0, weights)`)

1. **Weights:** 20 entries, one per member index. The tables at `0x5e36f0` and `0x5e3690` order them as members 1-9, 11-19, 21-22.
   - **Skill Drop Boost** (kind 24, sum from `FUN_000caaa0(…, 0x18)`): the played member's entry (save `+0x464488` via `+0xb6e`) gets this sum when it is above 0 (`0x5e873c` = 0.0). Every other entry gets 0.
2. **The draw** (`FUN_001f2ab0`, case 0):
   - **Group:** `FUN_000730a0` gives the current group (save `+0x8f768`). µ's uses indexes 0-8 with base 11; otherwise indexes 9-19 with base 9.
   - **Member:** r = xorshift128 >> 16 × 1/65536 (`0x5f65e0`) × the sum of (base + weight). The first index where the running remainder drops below 0 is the member.
   - **Card:** uniformly among the pool-0 rows of `s_reward_datas` whose card belongs to that member.
3. **Second draw:** when the result's rank byte `+0xc87` > 3 (S or better) and the Getting Skills Charge sum (kind 25) is above 0. The roll is xorshift × 1/65536 (`0x5e8738`) × 100 (`0x5e8734`); a second draw happens when the roll ≤ the sum.
4. **Skipped:** the whole block is skipped when `+0xc96` is set (S1: likely View Live Show).
5. **Other draws in the same function** (not ported): pool 3 for each support player whose flag `+0x51` is clear (profile cards; offline NPCs), and Drop Support (kind 23) pools 1-2 (boosters).

**Port group:** the played member's group. In the game the group switch and the played member always agree (R2 switches members within the group).

### The material drop (`FUN_000679a0`): traced, not ported

The port's `costume::RollDrops` (M7) gives each of the song's 18 materials its own chance roll. The game works differently:

- **How many:** a count N, uniform in [min, max] from `s_CommonParam +0x150 + i × 8`: (5, 8), (9, 13), (14, 18), (19, 23), (28, 32), (32, 36), (36, 40). The index comes from the result (`+0x8c`, not identified). Some cases add more (`param_8`, and kind 22 Wai-Wai! Booster Boost).
- **Candidates:** the song's 60 (chance, cap) pairs (`s_music_datas +0x15C`), each chance × two factors from `s_CommonParam` (`+0xf4[...]`, `+0x1a8`, `+0x1f0`, not identified).
- **Pass 1:** while N > 0, each candidate with cap left rolls against its chance and gives one unit.
- **Pass 2:** the units still owed are drawn by weight among the top five candidates.

**Material skills** (all via `FUN_000caaa0`; v = the sum of the kind's amounts):

| Kind | Effect in `FUN_000679a0` |
|---|---|
| 27 | every chance × (1 + v/100) |
| 30 | common yarn and cloth (item types 3, 4) chance × (1 + v/100) |
| 31 | with chance v %: the cap of yarn types (3, 5, 7, 9, 11) × `0x5e5d0c` |
| 32 | the same for cloth types (4, 6, 8, 10, 12) |
| 33 | keys (types 1, 2) chance × (1 + v/100) |
| 34 | with chance v %: each key gained gives one more |
| 35 | keys, under a flag of the current costume (key bonus): chance × (1 + v/100) |

Kinds 28 and 29 (Converting Threads/Fabric) are not read here. *Hypothesis:* they act where the drop lists are split by type (the `local_2a0`/`local_2c0`/`local_2e0` lists after the loop), turning common units into the group's own.

**Why not in S6:** these multiply terms of the game's algorithm (count, caps, factors) that the port's `RollDrops` does not have. Grafting them onto `RollDrops` would be a guess on top of a guess. The right order is to port `FUN_000679a0` first, then add the skill terms. That is a step of its own (proposed as **S6b** in the plan).

## Change

**`src/game/card/card.h/.cpp`:**
- **`SkillSum(member, kind)`:** the played member's set cards' amounts.
- **`DrawSkillCard(member, boost)`:** the weighted member, then a uniform card from the drop pool.
- **`RollSkillDrops(member, rank)`:** the first draw, plus the second at rank > 3 with the charge %. The save is not changed; the caller adds each card.

**`src/app/main.cpp`:** after a finished live, the drops go into the save (`AddSkill`; a duplicate raises the level). Log line: `skill card: 72015 Lucky Key Boost (member 7), level 0 -> 1`. The drops and the materials go into `LiveResult`.

**The result's Items Obtained page** (`src/app/result_screen.cpp`, `uil0003_RewardLayout00`, matching shadPS4 `s22`):
- **Turning the page:** a key on the results turns to it. Left/Right pick the card shown; any other key ends.
- **Title:** `res_title_text01_T` u 0.5, "Items Obtained".
- **Items Obtained:**
  - one card icon per dropped card (`uip0020_RewIcon00_01`-`_08`; `_00` sits under the left arrow of the scrolling list);
  - the focused one uses the "on" frame.
- **Materials Obtained:**
  - "[Key Materials]" (2 slots) and "[Standard Materials]" (16), messages 548/549;
  - each row shows the icon, "×gain" and "(new total)".
- **Skill Card panel:**
  - the card picture;
  - "Skill Card" (550);
  - message 560: the member name (messages 197-216), the skill and the level. "Lv. 1", or "Lv. 1 → Lv. 2" (554/555/556) for a duplicate.
- **Fix:** the result header showed Aqours for every song. It now follows the song's group, as S4 did for the song select.
- **Route screen name:** `result_items`. Log: `result: items obtained: 1 skill cards 72015, 5 materials`.

**`src/engine/ui/ui_screen.cpp`:**
- **Number boxes** of parts borrowed from another package (here 00_common's material rows) now load from that package's `ui_number.bin`/`numtex_datas.bin`, like text boxes already did. Number textures are keyed by (package prefix, id).
- **Glyphs:** the second glyph row of the number textures (`/ ( ) + - % × *`, slots 10-17) is drawn, so "×4" and "(10)" render.

**`tests/unit/message_test.cpp`:** `--dump` prints every English message with its id. This is how 548-560 and 197-216 were found.
