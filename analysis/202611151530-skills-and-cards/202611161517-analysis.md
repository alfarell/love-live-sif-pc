**The worn costume:** live `[0x3b]` is the worn member card. `FUN_00010770` finds it in `s_member_card_datas`; its `+0x14` % 1000 is the costume id. `FUN_0006ed00` finds that costume's `s_dress_datas` record, whose `+0x04` is the costume type 0-4.

**`s_itemCombineDatas`** (`item.pac/item_combine_data.bin`, 25 floats): a circulant 5 × 5 table, 1.5 on the diagonal, then 1.2, 1.15, 1.1, 1.0. Costume type and song type are both 0-4, and messages 803-812 ("Key Materials drop more easily when worn during songs that yield both beads and frills", …) name five costume types per group. So a costume made for the song's material pair gives ×1.5.

**Two indexes as hypotheses:**
- **Unit count by rank:** save `+0xf0914` is a 7-valued number also used for the Friendship gain (`FUN_00078860(+0xf0914, difficulty)`) and for a stage unlock at > 2. The port reads it as the clear rank D-SSS. *Evidence:* the two rank-D shadPS4 lives of S2 gave 7 units each (`s22`), inside rank D's 5-8.
- **Key bonus flag** (save `+0xf0a40` bit 1): its setter is not traced. The port reads it as "the costume type equals the song type", the same match the ×1.5 rewards and messages 803-812 describe.

**Constants:**
- `0x5e5d04` = 1/65536;
- `0x5e5d08` = 100;
- `0x5e5d0c` = 1.5 (the cap factor);
- `0x5e5d10` = 2.0 (the key double flag);
- `0x5e5d14` = 0.

## The algorithm (ported as `costume::RollDrops`)

1. **Count:** N = min + ⌊u × (max − min + 1)⌋. A booster adds 10, and Wai-Wai! Booster Boost (kind 22) adds another 10 with its chance; neither is ported.
2. **Weights:** each material with cap > 0 and chance > 0 gets weight = chance × difficulty factor × costume factor.
   - **By type:** keys (types 1, 2): × 1.2 and × kind 35 when the key flag is set, then × kind 33. Common yarn/cloth (3, 4): × kind 30. Then all yarns (odd types) take the kind 31 cap factor and all cloths (even) take kind 32's.
   - **Everything:** × kind 27.
3. **Order:** a stable sort by weight, highest first (`FUN_00069ca0`), then a stable partition with keys first (`FUN_0006b0d0`).
4. **Pass 1:** rounds over the list while N > 0.
   - Each material with cap left uses one cap and gives one unit when u ≤ its weight.
   - A round with no cap left anywhere ends the pass.
5. **Pass 2:** sort again by weight (`FUN_0006c160`, keys not first). While N > 0, pick by weight among the first five and give one unit.
6. **Each unit given:** joins the result list (item, count) in first-gain order. With kind 34 active, a key unit comes twice. The result index is also filed by type: common yarn (3), common cloth (4), group yarn (5, 7, 9, 11) and group cloth (6, 8, 10, 12).
7. **Conversions:**
   - **Converting Threads:** if group yarns dropped, each common yarn result gives up ⌈v × count / 100⌉ (`vroundss` mode 10 = round up). The total is shared evenly among the group yarns, and the remainder goes one by one to random ones.
   - **Converting Fabric:** the same for cloth with kind 29. The kind of the first conversion is read as 28; the decompile drops that call's second argument.

**The skill terms** (v = the kind's sum, `FUN_000caaa0`):
- **Factors:** kinds 27, 30, 33, 35 are factors (v + 100) / 100.
- **Rolled once per live:** kinds 31, 32, 34 roll u × 100 ≤ v. Kinds 31/32 then multiply the caps by 1.5; kind 34 doubles every key unit.

**This corrects S6:** kinds 28 and 29 are read in this function, at the conversion step.

## Change

**`src/game/costume/costume.h/.cpp`:**
- **New data:** `Recipe::type` (dress `+0x04`), `Data::song_type` (music `+0x158`), `Data::base_type` (record 0, for d000), and `DropRules` (`s_CommonParam` +0x150/+0xf4/+0x1a8 and `s_itemCombineDatas`).
- **`RollDrops(data, DropInput{song, rank, difficulty, dress, skills}, random, save)`:** the algorithm above. It replaces M7's guess of one chance roll per material, worth its whole "amount".

**`src/app/main.cpp`:** passes the rank, the difficulty index (variants 00-04 → 0-4, 10-13 → 5-8), the costume worn and the played member's material skill sums (`card::SkillSum`, kinds 27-35).

**`docs/formats/costume.md`:** the drop, the costume type, the song type and the skill table.

## Shortcuts and hypotheses (in code comments)

- **Rank as the count index:** see above.
- **Key flag:** the costume match. Its real setter is not traced.
- **Wai-Wai! Booster:** +10 units and kind 22 are left out, since there are no boosters.
- **Random numbers:** the game uses one xorshift128 stream; the port uses `std::mt19937`. Distributions match, sequences do not.
