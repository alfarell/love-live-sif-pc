# S1: skill cards in the eboot

Date: 2026-11-15 15:48 (Asia/Jakarta). Step S1 of `plan/202611151530-m11-skills-and-cards/202611151530-plan.md`. Follows the survey `202611151530-analysis.md`.

## Method

- **Ghidra 12.1.4 headless,** as in U5 (`analysis/202611010903-u5-live-rules/202611010917-analysis.md`): the decrypted eboot is copied into the session scratchpad and imported with `-loader-imagebase 0`. Functions are decompiled with `repository/tools/ghidra/DecompileFunctions.java`. The `.c` files stay in the scratchpad.
- **Disassembly:** `work/eboot.asm`, read with `work/m11/asm.py ADDR [LINES]`.
- **Address note:** `work/eboot-strings.txt` lists **file offsets**; the code's addresses are 0x4000 lower.
- **REA** could not analyse this ELF on Windows: its Ghidra provider takes only PE files there.

## The tables in memory

| Global | Content |
|---|---|
| `0xe038b8` / `0xe038c0` | `s_member_card_datas`: pointer and count (28-byte records) |
| `0xe038c8` / `0xe038d0` | `s_skill_card_datas`: pointer and count (128-byte records) |

- **Loader:** `0x10400`.
- **Lookups:** count `0x109e0`, by index `0x109f0`, by id `0x10a00`, has id `0x10a40`, index of id `0x10a80`.
- **Level table:** skill card `+0x70` is the pointer to its level table, 48 bytes per level (the file stores an offset). `+0x6c` is the maximum level (10, or 1).

**Level row**, completing the survey:

| Offset | Meaning |
|---|---|
| +0x00 f32 | **duration in seconds** for timed skills (×1000 → ms, `0x5e89ec`); −1 = not timed ("[Automatic activation]") |
| +0x04 i32 | **amount**: a use count (Finale Support, Starting Combo Support) or a percent/points value (drop and material skills) |
| +0x08 i32 | **share for other members in %** (50 or 25; 0 = full) |
| +0x0C i32 | an alternative amount, used for kind 19 (More Friendship Points +) |

## Who carries skill cards

- **Every member has three skill slots.** In the save they sit at `+0x8fd7c + member × 0xdc` (three card ids).
- **Levels** come from the owned list; a card not found there counts as level 1 (`FUN_0007c4a0`).
- **Players in the live:** the live has up to 9 players, one per member on stage (`FUN_001ebfd0` adds one). Each player record holds its three cards and levels:
  - `+0xec`/`+0xf0`;
  - `+0xf4`/`+0xf8`;
  - `+0xfc`/`+0x100`.
- **Full strength:** player 0 is the **focused member**. The drop code calls this member "oshimen" (favourite); save `+0x464488` at the live start. That member's cards work in full.
- **Shared strength:** the other members' cards also work, at the level row's +0x08 share:
  - **Value sums** (`FUN_000caaa0`): `amount × share / 100`.
  - **Timed skills** (`FUN_000af350`): `duration × 0.5` (`0x5e89e8`), and only kinds 0, 1, 6, 13 and 38 (mask `0x400000a043`).

*Hypothesis:* the focused member is the favourite member (`uil0014_FavoriteSelect00`). S2 should confirm where the player picks it.

## When a live skill fires (`FUN_000a1df0`, the chart setup)

**Skill notes:**
- The skill slots map to the chart's phases: slot 1 to phase 1, slot 2 to phase 2, slot 3 to phase 3 (`FUN_00099620`: phase kind 3 → slot 2 and flag `0x40`; 2 → slot 3, `0x20`; else slot 1, `0x10`).
- In each phase, the **Rhythm Icon notes** (chart channels 2-4, the icon channels of `MarkIcons`) that belong to the slot's player become **skill notes**. They get:
  - the slot flag (`0x10`/`0x20`/`0x40` at note `+0x40`);
  - `0x400`, the icon flag;
  - for timed cards, a per-slot timed flag (`0x5e8530`: `0x4000000`, `0x8000000`, `0x10000000`).
- **Not known:** which player an icon note belongs to (`FUN_00099280`). *Hypothesis:* each of the nine icon notes is tied to one member.

**The Rhythm Icon bag** (`FUN_000a0d80`):
- **Size:** 9 minus the number of the focused member's set cards.
- **Real icons:** the bag holds this many real Rhythm Icons:
  - 9 − n for difficulty classes 0-1;
  - 5 − n for class 2;
  - 4 − n for class 3;
  - 3 − n for class 4 and up.
- The bag is shuffled with the game's xorshift128 generator (`0xe03a68`). Icon notes not taken by a skill draw from it in order.
- So **a set skill card replaces one Rhythm Icon chance**.

**Firing:**
- **Hit:** hitting a skill note fires its skill (handler `FUN_000af350`, vtable slot +0x60 of the live observers). A timed skill lasts `duration × 1000` ms from the hit (`FUN_000aef80`).
- **Score:** a skill note scores like a Rhythm Icon note. Note type `+0x118`; `× +0x11C` for slot-1 notes, as in U5.
- **Live start:** cards whose duration is −1 do not wait for a note. They are armed at the live start (`FUN_000ae3f0`) and consumed by their own events.
- **No chance roll:** there is no random roll on firing. The survey's "chance" reading of field +0x04 was wrong for the live skills.

## After the live (`FUN_000a68d0`, result; `FUN_0007cf30`, commit)

**Skill card drop** (`FUN_001f2ab0`, pool 0):
1. **Pick a member.** The current group (save `+0x8f768`, `FUN_000730a0`) gives the candidates:
   - µ's: members 1-9, weight 11 each;
   - otherwise: Aqours and Saint Snow, members 11-22 (member index table `0x5e36f0`), weight 9 each.

   The focused member's weight gets **+ the sum of Skill Drop Boost (kind 24)**.
2. **Pick a card** uniformly among that member's cards in pool 0 of `ll3::reward::s_reward_datas` (`common.pac/reward.pac/reward_data.bin`):
   - 404 records of 20 bytes: id, pool, …, item id at +0x10;
   - pool 0 has 285 skill cards: 19 per µ's member, 12 per Aqours member, 3 per Saint Snow member.
3. **One draw per live.** The draw is skipped in one mode (`+0xc96`; *Hypothesis:* View Live Show).
4. **A second draw** happens with chance = the sum of **Getting Skills Charge (kind 25)** %, when the result's `+0xc87` (from `+0xf0a34`) is above 3. *Hypothesis:* the rank, 4 = S.

**Cards that never drop:** the 130 skill cards outside pool 0 are exactly the 130 with the flag at record +0x7C. They come from tasks (92, survey) and Birthday Events.

**Other after-live skills:**
- **Drop Support (kind 23):** % chance of a Wai-Wai! Booster for the focused member (pool 1).
- **Friendship skills (19, 20)** add % of the Friendship gain.
- Booster and Friendship systems are not built, so these stay inactive in M11 (plan S6).

**Duplicates** (`FUN_0007cf30`):
- **New card:** added at level 1 (`FUN_00071ce0`).
- **Owned card:** its level goes **+1, up to its maximum** (record +0x6C).
- The result screen shows the old level and the new one.

- **Lookups:** `FUN_00071da0` and `FUN_00071df0` find an owned card.
- **Collection completion** (`FUN_000e3620`): owned cards of a member over all of that member's cards. It picks one of the messages 0x348-0x34D.

## Corrections to the survey

- **Field +0x04** of the level row is not an activation chance for live skills. It is a count or an amount.
- **Field +0x08** is the share for non-focused members.
- **There is no firing roll.** Skills fire on their skill notes (one phase per slot) or are armed at the start.
- **Effect kinds 24 and 25** act on the skill card drop (member weight and a second draw), as the survey said. `oshimenSkillRateInc` weights the focused member.
