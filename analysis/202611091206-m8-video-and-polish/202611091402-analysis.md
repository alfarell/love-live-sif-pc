# V5: first run, choosing the dump folder

Date: 2026-11-09 14:02 (Asia/Jakarta). Step V5 of `plan/202611091206-m8-video-and-polish/202611091206-plan.md`.

## Before

With no `[game] folder`, or a folder that failed `IsSifDump`, `main.cpp` showed an error box ("Start with --game …") and exited. A new user had to know the command-line flag.

## Change

- **`src/app/first_run.{h,cpp}`:**
  - **`ResolveDumpFolder(chosen, hint)`:**
    - accepts the folder if it is a dump; `IsSifDump` checks for `sce_sys/param.sfo` naming CUSA24620, `common/common.pac`, `sound/sound.pac` and `live/`;
    - otherwise accepts its `CUSA24620` subfolder, so the folder above the dump also works;
    - otherwise refuses with a hint in plain words. A folder holding a `.pkg` gets "the port needs the game as a folder: your own dump…"; any other folder gets what is missing.
  - **`ChooseGameFolder(start, problem)`:**
    - a message box explains the problem, with "Choose folder..." and "Quit";
    - "Choose folder..." opens SDL3's system folder picker (`SDL_ShowOpenFolderDialog`; its callback may come from another thread, so the result is passed under a mutex while the event loop keeps running);
    - a refused folder brings the box back with the reason; cancelling the picker returns to the box; Quit exits.
- **`src/app/main.cpp`:** on a missing or invalid folder, initialise SDL video and call `ChooseGameFolder`. The chosen dump is saved to `settings.ini` as before. Quit exits with code 2. `--game DIR` still works and is checked the same way. The add-on folders are still looked for next to the dump (`Extracted`, `DLC`), unchanged.
- **Scope:** the port reads only the user's own dump. Nothing about obtaining, decrypting or unpacking games was added. The `.pkg` hint only says that a folder is needed.

The P.T. and SIF folders were only listed and read; nothing was written there.

- **`tests/unit/first_run_test.cpp`** (new, 15th test program): a scratch folder with a `.pkg` is refused with the `.pkg` hint; an empty folder is refused and names what is missing; the dump itself is accepted; the folder above it resolves to `CUSA24620`.
