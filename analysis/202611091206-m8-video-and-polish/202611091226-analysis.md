## Three problems found, and their fixes

1. **pl_mpeg's memory buffer breaks with the bare video decoder.**
   - **Problem:** `plm_video_decode` calls `plm_buffer_discard_read_bytes` on every picture. On a `plm_buffer_create_with_memory` buffer this `memmove`s the caller's data and shrinks its length, so the buffer never reaches its end and `plm_video_rewind` reads moved data. Seen as `ended 0` at the end, and as the first decode after a rewind failing.
   - **Fix:** our own source. A callback buffer, `plm_buffer_create_with_callbacks`, whose load callback copies from our stream and marks the end like pl_mpeg's file source. It grows the buffer instead of reporting the end when `plm_buffer_has_start_code` scans ahead with discarding off; pl_mpeg's own file callback has that flaw.
2. **Sofdec's 11-bit intra DC precision.** This is the main finding.
   - **Problem:** the decoded frames were garbage (saturated colours, block noise), and 1-14 pictures per file went missing. A slice overran into the next picture's header (stream position 5 bytes past picture 100's start code in `monitor_001`). The `@SFV` header's `mpeg_dcprec` is 11: CRI encodes MPEG-1 with MPEG-2's intra DC precision.
   - **Fix:** a pl_mpeg patch, `plm_video_set_intra_dc_precision`:
     - DC size codes 9-11;
     - predictor reset `1 << (p − 1)`;
     - DC multiplier `8 >> (p − 8)`.
   
   `Movie` sets it from the header. The default stays 8, so standard MPEG-1 is unchanged.
3. **The last picture of streams ending in B-pictures.**
   - **Problem:** pl_mpeg returned the held last reference picture only if the final decoded picture was I or P. These GOPs end … P B B, so one picture was lost (149 of 150).
   - **Fix:** a pl_mpeg patch that returns it whenever a reference is held at the end.

## Corrections to the M8 survey (`202611091206-analysis.md`)

- **Counts:** there are **202** movie files, not 382. The 382 came from probing the subfolders twice. They split into 22 monitors, 117 song previews and 63 costume previews.
- **Frame rates:** monitors are 30 fps, song previews 59.94 fps, costume previews 60 fps. The M2 note "all 60 fps" is wrong; `docs/formats/cri.md` is corrected.
- **Codec:** the decoder is not stock pl_mpeg. Sofdec streams need the DC precision patch above.
