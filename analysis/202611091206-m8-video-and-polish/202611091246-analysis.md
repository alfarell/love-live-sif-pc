# V2: streamed textures and `--movie`

Date: 2026-11-09 12:46 (Asia/Jakarta). Step V2 of `plan/202611091206-m8-video-and-polish/202611091206-plan.md`.

## Code

- **`src/engine/render/renderer.{h,cpp}`:**
  - `Texture` gains `staging`, an upload buffer kept for streamed textures.
  - `CreateTexture(w, h)` makes an RGBA8 texture and its upload buffer.
  - `UpdateTexture(texture, rgba)` copies a picture through that buffer, in its own copy pass, outside a frame, as `UpdateMesh` does. Both the upload buffer and the texture are **cycled** (SDL3's `cycle` flag), so a frame still in flight keeps sampling the previous picture; nothing waits for the GPU.
  - `Release(Texture&)` also frees the upload buffer.
- **`src/app/main.cpp`:** a developer flag `--movie VFS_PATH`. In the M3 check loop it plays a movie in place of the `--show` texture, looping, with the picture picked from the wall clock (`floor(t × fps) mod frames`). It uploads only when the picture changes and logs the average decode + upload time. Use `--play none` for silence.

## Notes

- **Looping:** going back to picture 0 rewinds and decodes from the start; GOPs are short, 13 pictures.
- **Colour:** pictures are uploaded as RGBA8 UNORM like the other textures, with pl_mpeg's BT.601 YCbCr → RGB on the CPU. *Hypothesis:* that matches the game's colours; this will be compared on screen in V3/V4.
