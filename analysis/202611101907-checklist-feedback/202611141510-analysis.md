## What the banner part holds

`ui2/10_top_menu` `uip0006_SubMenuList01`, the submenu banner:

| Nodes, layers | Texture | Look |
|---|---|---|
| `menu_select01_off` (material `mode_sub00_on`) | `top_mode_sub00_on_T` | white banner, pink text |
| `menu_select01_on` (material `mode_sub01_on`) | `top_mode_sub01_on_T` | green / pink / red / purple / blue / orange banner, white text |
| `complete00`, `new00` | markers | hidden by the port, as before |

**Both layers are visible by default**, and `on` is drawn over `off`. So before F1 every banner looked focused (green), which is why the user could not see which entry was chosen.

**The part's clips** (decoded with the BMA chunk layout of `src/engine/formats/bmar.cpp`):

| Clip | Length | Tracks |
|---|---|---|
| `a013` "active" | 20 frames | `on` visible from frame 0; `off` hidden at frame 20; `on` scaled 0.78 → 1.05 → 1.0 (a bounce) |
| `a014` "inactive" | 8 frames | `on` scaled 1.0 → 0.78; colour of `mode_sub01_on` and `_charaTex_mark00` 255 → 0 |
| `a020` "switch" | 22 frames | UV offsets choosing the label (used before, on layer 1) |
| `a001` "in" | 11 frames | colour 0 → 255 (fade in) |

The game's frame (`work/shadps4-run/v0-05.png`) shows the focused entry green and the others white with pink text.

## Change (`src/app/top_menu.cpp`, `Apply`)

- **Focused banner:** plays `a013` on layer 0 when the focus changes. The label clip stays on layer 1.
- **Other banners:** no clip, and their `menu_select01_on` node hidden (`UiScreen::HideNode(instance, node, …)`), so the white `off` layer shows.
- **The clips replay only when the focus moves** (`focus_changed`), so a held focus does not restart its bounce.

`a014` is **not used.** Its colour fade to 0 is drawn by the port's UI shader as opaque black, not as a fade-out; the first try showed black banners. *Hypothesis:* the game draws that material's colour with its alpha, so 0 means invisible. Hiding the node gives the same end state.
