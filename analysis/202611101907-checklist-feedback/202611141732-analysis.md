# F3: note speed as the game's "Rhythm Icon Speed"

Date: 2026-11-14 17:32 (Asia/Jakarta). Step F3 of `plan/202611101907-checklist-fixes/202611101907-plan.md`. The table and the messages are described in `202611101907-analysis.md` §3.

## Change

| Where | Before | Now |
|---|---|---|
| `settings.ini` `[play]` | `approach_ms` 400-3000 | `note_speed` 0-4 (default 2, Normal). An old `approach_ms` becomes the nearest level of the middle row (1700, 1500, 1300, 1050, 800 ms), so the old default 1300 maps to Normal. |
| Options → Game Settings | "Note speed", 0.4-3.0 s | the game's words: message 711 "Rhythm Icon Speed", values 728-732 (Slow, A Bit Slow, Normal, A Bit Fast, Fast), in the chosen language; English fallbacks if `message.pac` is missing |
| Live | one travel time for every chart | `s_CommonParam` +0x00, row = the chart's difficulty index (`s_live_datas` +0x14), column = the level. The log line is `live: difficulty index N, note speed L, travel T ms`. |
| Command line | none | `--approach MS` overrides the table, for tests |

Code:
- `ScoreRules::difficulty` and `approach_ms` are read in `song.cpp` `LoadScoreRules`;
- `live_screen.cpp` reads the travel time from them;
- the options row is in `options_screen.cpp`, which now loads `Messages`; it is the first screen to use the message table;
- the conversion of old settings is in `settings.cpp`.

## Is the row the difficulty index?

**The charts' indices** (port log, song 0340):

| Variant | Index |
|---|---|
| `_00` arcade Easy | 0 |
| `_01` arcade Normal | 1 |
| `_02` | 2 |
| `_03` | 3 |
| `_04` | 4 |
| `_10` | 5 |
| `_11` | 6 |
| `_12` | 7 |
| `_13` | 8 |

So at Normal, Easy should travel 1900 ms and Normal 1600 ms.

**The game** (shadPS4 G0 runs, no input, default settings, frame timestamps in the file names, about 0.26 s apart). Time from a note's first visible frame beside the mic to its arrival at its ring:

| Run | Note 1 | Note 2 | Visible travel |
|---|---|---|---|
| Easy (`g0-easy`) | frames 0111→0117 (29.07→30.65 s) | 0120→0126 (31.44→33.01 s) | about 1.58 s |
| Normal (`g0-live0340`) | 0105→0110 (27.57→28.88 s) | 0110→0115 (28.88→30.20 s) | about 1.3 s |

**The two runs differ in the same ratio as the table** (1900 / 1600 ≈ 1.6 / 1.3). The visible part is about 0.82 of the table value in both. *Hypothesis:* the first part of the path is hidden under the mic icon, so the note is first seen when it comes out from under it.

**The port, measured the same way** (`work/m9/f3_easy_sheet.png`, song 0340 Easy, table 1900 ms, a shot every 0.2 s):
- the first note is first visible at 1.64 s;
- it is judged at about 3.2-3.3 s;
- so about 1.6 s visible, matching the game's 1.58 s.

The port's notes start under the mic in the same way. So the table row = difficulty index at Normal fits both runs. The other reading, one row faster or a default of "A Bit Fast", would give 1.3 s visible on Easy instead of the 1.6 s measured in both games.

**The eboot** was searched for the lookup (callers of the `s_CommonParam` getter `0x946a0`, and every `x*5` index followed by a 4-byte load). No reader of +0x00 was found: the hits are other parameters and font tables. The code that indexes the table is still **not traced**. The row mapping rests on the frame measurement above.

## Checks

- **Unit tests:**
  - `live_test`: song 0340/00 has index 0 and 2300 … 1300 ms; 0340/01 has index 1 and 1600 at Normal; 0010/04 has index 4, Slow 1200, Fast 650;
  - `save_test`: old `approach_ms` values 1300, 900 and 3000 become levels 2, 4 and 0; `note_speed` wins over `approach_ms`; out of range is clamped; the setting survives a save and load round trip.
- **Routes:**
  - `options_1_change`: Right on the row expects `note speed A Bit Fast`, and a new shot `options_game` shows "Rhythm Icon Speed" and "A Bit Fast";
  - `options_2_kept`: the value is still there after a restart.
