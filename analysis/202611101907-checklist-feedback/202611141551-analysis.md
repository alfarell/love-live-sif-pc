# F1b: menu wheel and submenu layout

Date: 2026-11-14 15:51 (Asia/Jakarta). This is a follow-up to F1 (`202611141510-analysis.md`), made after the user's "Menu Wheel and Submenu Layout Correction" request.

## What was wrong, and why

The comparison is the port against the game's frame (`work/shadps4-run/v0-05.png`). Captures are `work/m9/menu_compare2.png` (port above, game below) and `work/m9/modes_sheet.png` (all six modes).

| Symptom | Cause | Fix |
|---|---|---|
| Wheel icons black or missing; every layer of an icon drawn at once | The wheel icons (`uip0004_MenuList00`) got only the label clip `a020` on layer 1. Layer 0 had no clip, so the icon, the plain circle, both banners and the reflections all drew together. | `top_menu.cpp` `Apply`: layer 0 plays `a013` "active" on the current-mode slot (slot 3) and `a005` "unfocus" on the others, replayed only when the mode changes. |
| Black wedges and a dark band over the icons | Meshes named `*_add*` (`reflection_add00`-`02`, `list00_bg_add00`) are black textures with a light streak, meant to be **added** to the picture. The port drew them alpha-blended, so their black showed. | `renderer.cpp`: a second UI pipeline `ui_add_` (blend `dst = ONE`). `scene_model.cpp` `Additive(node)` picks it for `_add` nodes. |
| The submenu's first banner drawn away from the fan (behind the others) | `bmar::Pose` treated a parent index of 0 as a root. That holds only for 3D models, whose node 0 is `bml_axisNode`. In UI layouts node 0 is a real node (e.g. the list's first slot holder), so its children lost its transform. | `bmar.cpp` `Pose`: parent 0 counts as root only when node 0 is named `bml_axisNode` (checked: `001_stageoflive.bmarc`). |
| Dark brown band with large stars behind the wheel (the game shows the room, a faint white band and a thin orange arc) | `uip0003_MenuEf00` node `list00_bg_ef_mask00` (texture `top_charabg_mask00`, an opaque black quarter ring) is a **mask**: a shape that only limits where the scrolling member marks show. The port drew it as colour, so the translucent `top_charabg_circle00_01` over it looked brown. | `scene_model.cpp` `Mask(node)`: `*_mask*` nodes are not drawn. |
| Fading banners and icons turned black | Focus clips (`a005`, `a014`) "fade" a layer by taking its colour to 0. | Colour exactly 0 is not drawn (`scene_model.cpp`, recorded shortcut). |

**How the band was found:** captures with `--ui 10_top_menu:uil0001_TopMenu00 --ui-hide <node>` for each candidate (`work/m9/band_test.png`), then the part's textures converted with `tools/tex2png.py`. Only `list00_bg_ef_mask00` uses a mask texture in the extracted UI; no other screen is affected.

## Layout

No positions are hardcoded. The submenu banners sit on the layout's own slot nodes (`menu_banner_onNN`), each with its rotation. That fan places the list beside the active icon, top to bottom. The port picks the layout by entry count:

| Entries | Layout | Modes |
|---|---|---|
| 2 | `uil0008_SubMenuList02_act` | Costumes, Additional Purchase |
| 3 | `uil0007_SubMenuList01_act` | Event |
| 4 | `uil0011_SubMenuList03_act` | Play, Options |
| 5 | `uil0006_SubMenuList00_act` | Collection |

Navigation is unchanged: Left/Right change the mode, Up/Down the entry, Enter chooses.

## Validation (the request's 8 points)

1. **Every wheel item shows its icon and plate.** Pass: all six modes in `modes_sheet.png`.
2. **No black placeholders.** Pass: the wedges, the band and the black banners are gone.
3. **Selecting a mode shows its submenu.** Pass.
4. **The submenu is a vertical fan.** Pass.
5. **The list sits beside the active icon.** Pass.
6. **The 2-, 3-, 4- and 5-entry lists.** Pass (table above).
7. **No overlaps.** Pass.
8. **Navigation.** Pass: route `boot` (Down → `mode 0, entry 1`) and the mode captures (Right, then Down, in each mode).

## Known limits

- **Masked marks are not clipped.** Without a stencil pass (drawing that limits later drawing to a shape), a member mark ("ほ") can show past the band edge; in the capture a few sit right of the submenu. The game also shows marks near there (they scroll), so this was left as a shortcut.
- **Fades.** A clip colour fading through dark values still darkens instead of turning transparent.
- **The wheel turns in whole steps.** The game eases between steps with clips 11/12; this was already a recorded shortcut.
- **The `bmar::Pose` change affects every UI layout** (77 files have node 0 as a parent). All routes were re-run; results are under Checks.

## Checks

- **Unit tests:** 15 of 15 pass (Debug; the dump-based ones run with the dump path).
- **Routes:** 21 of 21 pass (Release, `tools/routes.py --shots`). The 19 shots (`work/m9/routes_sheet_new.png`) match the earlier run for every screen except the top menu, which now matches the game. So the `bmar::Pose` change shows no regression elsewhere. The black half-disc on Button Controls was there before and is not part of this change.
