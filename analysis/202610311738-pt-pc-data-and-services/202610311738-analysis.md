## 1. Data access (`src/engine/fs`)

### Vfs

- **API** (`fs/vfs.h:18-44`, checked):
  - `Mount(game_dir)`;
  - `ReadFile(path)` / `ReadFileUntraced(path)`, which return `optional<vector<uint8_t>>`;
  - `LoadPackage(path)`, which returns a `shared_ptr<FoxPackage>`, plus `UnloadPackage` and `LoadedPackages`;
  - `MissingCorePackages`, `ToArchivePath`, and raw access to the PSARC (`Archive()`) and QAR (`Textures()`).
  - Lookups are by **string path**; Vfs has no hash-based lookup.
- **Mount** (`fs/vfs.cpp:17-34`): opens fixed-name `chunk1.psarc` and `texture.qar` and fails if either is missing. `ReportDataDifferences` (`:63-117`) only logs.
- **Path mapping** (`vfs.cpp:119-134`): backslash → `/`, the prefix `/Assets/` → `as/`, leading slashes stripped. The result is looked up in the PSARC manifest, which is entry 0 split on newlines (`fs/psarc.cpp:74-94`).
- **Lookup order** in `ReadFileUntraced` (`vfs.cpp:189-219`, checked):
  1. mod override;
  2. every loaded FPK package, by entry path;
  3. PSARC by name;
  4. a loose file `game_dir/<archive path>`.
- **Textures bypass Vfs:** `ftex` reads the QAR directly with `qar.Read(PathCode64(name))` (`assets/ftex.cpp:81`, checked; also `:101`, `:132`).
- **Threading:**
  - one mutex around the package map (`vfs.h:42`, `vfs.cpp:139-194`);
  - the PSARC and QAR readers each hold one `FILE*` behind a mutex, so reads are serialised (`psarc.cpp:130`, `qar.cpp:65`);
  - the active mod set is an atomic pointer (`mods.cpp:19`).
- **Caching:** only parsed FPK packages are cached, whole, in memory (`vfs.cpp:140-162`, `fpk.h:37`). Plain reads are not cached.

## 4. Lua script layer (`src/engine/script`)

- **VM:** `LuaVm` wraps one Lua 5.1 state with the full standard library (`luaL_newstate` + `luaL_openlibs`, `script/lua_vm.cpp:40-43`, checked). `RunChunk` is a protected call with a traceback (`:66-88`). `CallTableFunction` is how C++ calls into scripts (`:102-125`). `RegisterModule`/`SetModuleNumber`/`SetModuleString` fill globals (`:127-148`). No sandbox for game scripts (`docs/lua_api.md:13-15`).
- **The original game's Lua runs.** `Game::Init` runs P.T.'s own setup scripts: `ShParameterTables.lua`, `ShGimmickSetUp.lua`, `motion/setup.lua` (`game/game.cpp:77-80`, checked). They are read from the archive and decrypted when wrapped (`fox::IsWrapped`/`Unwrap`, `game.cpp:137`, checked). Every `.lua` in a stage's `.fpkd` runs when the stage loads (`game/stage_manager.cpp:148-149`, `game/script_host.cpp:26-34`). C++ calls `gameState.<Step>()`, `<file>.Exec(ctx)` for traps, and `<file>.OnMessage(...)` (`script_host.cpp:48-98`; contract `docs/lua_api.md:29-36`).
- **Bindings:**
  1. `RegisterStubApi` installs about 150 logging no-ops (`game/script_api.cpp:20-112`).
  2. Entity handles are added (`game/lua_entity.cpp:401`).
  3. `RegisterGameBindings` overwrites the stubs that are implemented: Fox, GameFloorLevel, GameSystem, SoundDaemon, GameObject, ShGameMainControl, GameController, FadeFunction, DemoDaemon, ShDemo, TppEffectUtility, ShNazoManager, Gimmick, ShGameStatus, ShParameter, plus the port's own PtDebug (`game/script_bindings.cpp:489-553`; `docs/lua_api.md:38-212`). Remaining stubs: `docs/lua_api.md:214-242`.
  - `--script-test` runs every archive script against the stubs (`main.cpp:617-644`).
- **Mod sandbox** (`script/mod_lua.*`):
  - a separate Lua state with a 64 MB allocator cap (`mod_lua.h:27-28`, `mod_lua.cpp:84-99`);
  - an instruction-count limit of 20 million (`mod_lua.cpp:64`, `:101-107`);
  - a per-mod `setfenv` environment with whitelisted libraries; precompiled chunks are refused (`:17-20`, `:216-312`);
  - events FloorEnter, StepChange, Tick, Message (`mod_lua.h:18`).
- **Class:** `LuaVm` and `ModLua` are generic Lua tools. The bindings and stubs are **Fox/P.T.** (they re-implement Fox Engine's Lua API). **For SIF: not applicable.** SIF has no script VM (Part 3, section 5), so there are no original scripts to run. A mod Lua layer would be an optional extra.

### `Game::Init` and `Game::Update` (subagent report)

- **Init** (`game.cpp:61-99`):
  1. set the save folder;
  2. `scripts_.Init()`;
  3. stage callbacks;
  4. load `resident.fpk`;
  5. run the three setup scripts;
  6. resolve models, load player animation;
  7. seed the RNG;
  8. set `first_boot`.
- **Update(dt, input)** (`game.cpp:190-344`):
  1. pause and reload checks;
  2. counters and a 30 Hz "game frame" flag;
  3. the step machine, mod Tick, stage streaming;
  4. messages and demos;
  5. deferred collision rebuild;
  6. player, footstep sounds, traps;
  7. objects, effects, light, camera;
  8. audio last: listener from the camera, an RTPC (a Wwise game parameter), `audio_->Update`.

### `RunGame` frame loop (`src/main.cpp:5283-7650`)

- **Fixed timestep:**
  - `step = 1 / tick_rate` (default 60 Hz). `accumulator = paced ? min(accumulator + dt, 0.25) : step` (`main.cpp:6367-6368`, checked). At most 8 ticks per frame (`:6400-6492`).
  - Rendering interpolates with `accumulator / step` (`:6958-6968`).
  - `dt` comes from the SDL clock, clamped to 0.1 to 100 ms (`:6094-6098`).
- **Per frame:**
  1. `PumpEvents` input (`:5887`).
  2. For each tick: scripted input `script.Apply` (`:6406`); one of `lisa_date`/`theater`/`game.Update(step)` (`:6418-6439`); `vfx_scene.Update`; `ui.Update` (`:6444-6447`).
  3. Offline audio render for capture (`:6458`).
  4. `game.CollectDraws` (`:6956`) and `game.ViewCamera()` (`:6935`); lighting by `RenderSceneBuilder::Build` (`:7136`).
  5. `app.scene.Render(camera, draw_items, lighting, dt)` (`:7295`, checked; `:7146` is the VR path, correcting Part 1 section 9).
  6. `renderer.EndFrame` (`:7299`).
  7. Frame cap: a user limit, 60 fps in menus, `SDL_DelayPrecise`, or Reflex under frame generation (`:7515-7559`).
- **Headless:** `--headless --frames N` runs with no window or audio device and saves off; it can take a screenshot and logs input-script expectation failures (`:5287`, `:7612-7628`).
- **Input scripts:** frame-numbered commands plus waypoint commands (goto, look, wait, expect, shot) (`game/input_script.cpp:38-60`, `input_script.h:22-136`). Used by `tests/walkthrough/*.txt` and `tools/walkthrough.py`.
