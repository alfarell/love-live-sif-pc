# Gameplay feedback: the live screen against the game

Date: 2026-11-07 22:12 (Asia/Jakarta). This note covers analysis only. No code or asset was changed.

The user gave six feedback items with three screenshots of the game (song "Bokura no LIVE Kimi to no LIFE", µ's). This note compares those against:
- the port's live screen (`repository/src/app/live_screen.cpp`);
- the game's own assets;
- fresh captures of the port: `work/gameplay-fix/port_live_14s.png` and `port_live_30s.png` (song 0010 challenge, autoplay).

Asset sheets made for this note are in `work/gameplay-fix/` (not committed).

Terms used here:
- **Atlas:** one texture holding many small pictures in a grid of cells.
- **Cell (c, r):** column c, row r of that grid, counted from 0.
- **`.fad`:** the game's 2D animation files.

The game's own names, from `message.pac`:
- The notes are **"rhythm icons"**.
- The collectibles are **"Finale Rhythm Icons"**. Message 502: "Get all the Finale Rhythm Icons to reach a high score! If you have an HR Card, you can activate a Finale Focus, too!"
- Game Settings has a **"Rhythm Icon Button Display"** row (message 714).

## 1. How the port draws a live today

Everything is in `RunLive` and its `Playfield` helper (`live_screen.cpp`).

| Part | Code | What it does now |
|---|---|---|
| Lane positions | `Playfield::Load`, `ui_ingame_layout.bin` `layout_judge_ring01-09` | Correct, from the game's layout (1920 × 1080 canvas) |
| Note indicator (ring) | `field.ring` = `ui_ingame_notes` cell (1, 0) | The **pink note ring**, at 1.68 × ring size. No button icon |
| Moving note | `field.note` = `ui_ingame_notes` cell (group, 1) | The **yellow finale disc** (star, anchor or snowman) for every note, all song long |
| Hold note | `field.trail` cell (2, 0) as a row of discs every 40 ms, end disc, `ui_ingame_longnote_circle_01` glow while held | Dotted trail, not a line. Same look held or not |
| Simultaneous notes | `DrawBar` with the orange bar cell (1, 3) between notes of the same time | A long orange bar joining the notes |
| Judgement text | `judge_fad[grade]` drawn at (960, 470), from the latest judgement only | Centre of the screen. One text at a time |
| Combo | `DrawCombo(combo, 960, 470)`, full opacity | Centre of the screen, under the judgement text |
| Score | `live::Judge` (`src/game/live/judge.cpp`) | Game formula (U5 notes). No finale part |
| LOVELIVE! marks | HUD `uil0001_Ingame00`, `uip0003_FFmark` | Shown at their default (9 grey stars). Never filled |
| Chart | `live::ParseChart` (`chart.cpp`) reads only `_ch1.scd` | Lane, time, hold end. Nothing else |

Data that helps the fix:
- The `flash` and `flash_grade` arrays (per lane) already track the latest judgement per lane, so per-lane judgement text needs no new state.
- `Song::group` (0 µ's, 1 Aqours, 2 Saint Snow) is already loaded from `s_music_datas` +0x10.
- `PadSlots` (`src/app/input`) holds the saved pad mapping per lane, which the icons need.

## 3. The chart already says where the icons and the finale are

The port reads only `score_<song>_<variant>_<title>_ch1.scd`. The other channel files of the same chart carry the finale data. Census of songs 0010, 0020, 0050 and 0340, all nine variants each (`work/gameplay-fix/census.csv`):

- **`ch2`, `ch3`, `ch4`:** each holds exactly **9 notes**, in every chart. That is one per LOVELIVE! letter.
  - Their note numbers are lane numbers (55-63).
  - Each channel has 3 notes in each of three phases (below).
  - Their times do **not** fall on a `ch1` note: they are 0-720 ticks off (one beat is 480).
- **`ch5`:** 10 long notes that cut the song into phases:
  - three phases with three choices each: note numbers 60/63/66, then 61/64/67, then 62/65/68;
  - then **note 69 from its start to the end of the song**. For 0010 that is 93.7 s to the end; for 0340 it is from 103.9 s.
  - The phase times are the same for all difficulties of a song.

*Hypothesis:*
- Each phase uses one of three icon sets: `ch2`, `ch3` or `ch4` (note 60 + 3 × set + phase).
- The game picks the set per phase, chosen at random or by rule.
- Each event marks the nearest `ch1` note, or the next one, as a Finale Rhythm Icon.
- Note 69 is the **finale section**.

Which `ch1` note gets the icon, and how the set is chosen, is not known. It needs an eboot trace (open question Q1).

## 4. Score: what is known about the finale boost

From the U5 notes (`analysis/202611010903-u5-live-rules/202611010949-analysis.md`):
- `s_CommonParam` +0x120 = **3.0** is a score multiplier used when check `0x93D00` is true. It was called a "skill multiplier" then.
- Note flags 0x800, 0x1000 and 0x2000 and counters +0x1B4-0x1BC (2000 / 6000 / 30000) were found but have no known meaning.
- The rank thresholds go **above 100%**: 1.025 and 1.2 of the all-Perfect score. Those ranks are only reachable with bonus points, which fits a finale boost.
- The eboot also names `addFinalePt`, `autoFinaleIcon`, `costumeItemFinaleFocus` (skills and costume effects) and `FinaleFocusCnt`. Finale Focus itself needs an HR card, which is not built.

*Hypothesis:* `0x93D00` is "finale active", and finale notes score × 3.0. This must be traced (open question Q2) before the score changes.

Labels used below:

### Item 2.1: normal notes

- **Game (Seen):** pink ring (1, 0) with a dark pink fill and the lane's button icon. The icon depends on the "Rhythm Icon Button Display" option.

### Item 2.2: Finale Rhythm Icon notes and LOVELIVE!

### Item 4: simultaneous notes
- **Now:** one long orange bar between the notes.

  - **Assets** fit the description: brackets (3, 3) / (4, 3) and short bars (1, 3) / (2, 3) on **each** note, orange or blue. Option preview `opt_gam_note00_03` shows it.
  - **User:** colour alternates per simultaneous group (orange, blue, orange …).
  - **User:** a vertical line in the indicator when the group is pressed together.
- **Gap:**
  - per-note decoration instead of the joining bar;
  - a group index per note;
  - the "satisfied" check and its vertical line. Which asset draws that line is not identified (Q3); candidates are the bar cell turned 90°, or `opt_gam_note00_01`'s bar.

### Item 5: judgement text
- **Now:** one text at the screen centre.
- **Game (Seen):** "MISS" over the lane's ring. In screenshot 2 the ← ring centre is at (377, 734) and the text at about (383, 637), so about 97 px above the ring centre on the 1080-line canvas.
- **Gap:** draw per lane, from the per-lane `flash` state, so two lanes judged at once each get their text. The fad's own anchor inside its 400 × 400 canvas decides the offset; check it on a capture.

### Item 6: combo
- **Now:** at (960, 470), opaque.
- **User:** a bit lower, about 40% opacity. The screenshots show no combo (it was broken by a Miss), so the exact spot is the user's choice.
- **Gap:** y and alpha in `DrawCombo`. `Playfield::Draw` already takes a tint, so alpha is one value.

### Other differences seen (not in the feedback)

## 7. Risks for the fix

- `live::Chart` and `LoadSong` gain channel data. `sif_live_test`, `sif_sweep` and the result screen read them. Keep `ch1` parsing as it is.
- A finale score changes autoplay scores and the clear rate. `MaxScore` must then say whether it includes the finale; *Hypothesis:* the game's maximum excludes it, as the rank thresholds above 1.0 suggest. Existing tests use fixed charts without `ch5` and stay unchanged.
- The indicator cell has a different margin from the old ring. Sizes must be re-measured, or the rings will not match the layout's 152 px.
- Icons depend on `PadSlots`. A changed mapping must update the icons at live start.
- Draw order: indicator, then hold lines, then notes far-to-near, then judgement, combo and LIVE CLEAR. The hold glow stays at the ring.
