# M9 start: what "playable release candidate" needs

Date: 2026-11-09 16:47 (Asia/Jakarta). Survey for milestone M9 of `plan/202610311831-sif-port-roadmap/202610311831-plan.md`. Plan: `plan/202611091647-m9-release-candidate/202611091647-plan.md`.

## The M9 exit (roadmap)

The roadmap gives three conditions:

1. All headless routes pass.
2. A manual checklist of all screens is ticked.
3. No game data in the repository (scan check).

**Project completion criteria:** "M0-M9 ticked, all checkpoint reviews recorded, and the README states how to build and run with the user's own dump". The README part was done in M8 V6, through `docs/BUILD.md` and `docs/PLAY.md`.

## 1. Routes: none exist yet

**The plan:** the roadmap's repository layout planned `tests/routes/`, "headless input/chart routes (walkthrough style)". It was never built.

**What exists:**
- The M4 "headless autoplay route" became a unit test: `Autoplay` in `tests/unit/live_test.cpp` judges a chart without a window.
- The 15 unit test programs cover formats and rules.
- Screens were checked with one-off capture scripts (PrintWindow plus posted keys) during M6-M8. Those are not repeatable tests in the repository.

**The model, pt-pc (read-only):**
- `tests/walkthrough/*.txt`: 141 route scripts, one command per line: `swait N`, `sui menukey down`, `sexpect pcrow pc_archive`, `sshot {shots}/x.png`;
- `tools/walkthrough.py --exe … --game …` plays them without a window and checks the log. The README says it "is how I make sure a change did not break a loop".

**What the port offers for this:**
- **Input:** all 12 interactive screens (`RunTitle`, `RunTopMenu`, `RunSongSelect`, `RunLive`, `RunResult`, `RunCalibration`, `RunCostumes`, `RunMaterials`, `RunMissions`, `RunProfile`, `RunOptions`, plus the UI viewer) read input only through `sif::PollEvent` (`src/app/input.cpp`; 16 call sites; only the first-run picker waits on SDL directly). So a route player can inject key events in one place, without OS input.
- **State:** the screens log little (1-3 lines each, `live_screen` 10), and there is no "current screen" state. Routes need a few state reports to check against (`expect`).
- **Exit:** every screen already takes a frame limit, and `main.cpp` exits with codes 0, 1 and 2.
- **The first-run picker** is an OS dialog. A route cannot drive it through `PollEvent`; it is covered by `first_run_test` and the V5 check. Routes pass `--game`.

## 3. Asset scan

`py -3.14 -I repository/tools/no_assets_check.py . --all` checks every tracked file and every untracked file that is not ignored: game magics, SELF/ELF/PKG headers, protected names, binaries over 2 MB. Result today: **329 files, 0 suspicious**.

`work/` (extracts, builds, captures, the clean clone) is git-ignored and is not part of the repository.

## Open questions for the plan

1. **"Headless":** rendering with a hidden window (`SDL_WINDOW_HIDDEN`) may make `BeginFrame` fail on some drivers, and the screens then skip drawing. Routes must still advance, or they run with a visible but unfocused window. To be measured in R1.
2. **"Manual" checklist:** the user ticks it. The port's own captures (`--shots`) can prepare evidence for each item, but they do not replace the user's look.
