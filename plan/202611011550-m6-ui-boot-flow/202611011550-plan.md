# M6 plan: UI and boot flow

Created: 202611011550 (Asia/Jakarta). Roadmap M6 (`plan/202610311831-sif-port-roadmap/202610311831-plan.md`): "Boot → title → top menu → song select → live → result, with real UI assets (U3 resolved) and text from `message.pac`. CP3: screen and system inventory with an estimate". Findings: `analysis/202611011550-m6-ui-boot-flow/202611011550-analysis.md` (U3: no Flash runtime; `ui2` = BMAR quad layouts).

## Steps

1. **UI renderer.**
   - A 1920 × 1080 orthographic canvas, scaled to the window.
   - An alpha-blended quad pipeline in the 2D pass.
   - A `UiScreen` that loads a `ui2/<screen>_<lang>.pac`, its parts and layouts, and draws a layout (parts at their nodes).
   - Language default `en` (setting).
2. **Boot and title.** CRI logo → Square Enix logo → notice → title (BG, logo, blinking "Game Start", copyright). Confirm with a key, then the top menu.
   - Fixed timings (shortcut until `BTL` is decoded).
   - Verify by window captures.
3. **Text.** Find the font data and `message.pac` format, and draw the text boxes (version string, menu labels).
4. **Top menu** (`10_top_menu`). Navigate between entries; "Play Live Show" leads to song select.
5. **Song select** (`20_setup`). Pick a song and difficulty from `s_music_datas`/`s_live_datas`, then the M5 live screen.
6. **Result** (`95_result`). Grades, combo and score from the judge, then back to song select.
7. **Controller input** for menus and play (SDL3 gamepad).
8. **CP3:** inventory of all `ui2` screens and game systems, with estimates, in `plan/`.

Steps 1 and 2 come first because they test the format on the smallest screen. Steps 3 (text) and 7 (pad) are independent of 4–6.

## Rules

- Extract only the screens being worked on (`ui2/<screen>_en.pac`, about 13 MB each) to `work/extract/`.
- Screen captures go in `work/`, never in the repository.
- Timings and flow that are not traced are marked `shortcut:` in the code.
