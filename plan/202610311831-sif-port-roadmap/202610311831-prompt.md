- shadPS4 emulator source, GPL-2.0, reference and NID names only (READ-ONLY): D:\Games\PS4\shadPS4

Task: find the first unticked checklist item in the plan whose milestone is reached in order, and complete it (or a small coherent group of items in the same milestone). Stop at a checkpoint item (CP1-CP4) and ask me before writing the review decision.

How to work:
1. Timestamps from PowerShell `Get-Date -Format yyyyMMddHHmm` (Asia/Jakarta). Results go to analysis\<timestamp>-<topic>\<timestamp>-analysis.md; decisions and plan revisions to plan\. Never overwrite earlier files.
2. Read the actual files and data before concluding; cite file paths and line numbers or offsets; label guesses "Hypothesis"; keep an "Open questions" section.
3. Save notes as you go so a cut-off session loses nothing.
4. Code goes in repository\ (layout in plan §2). Generic engine code (src\engine) stays apart from SIF formats (src\formats) and SIF game rules (src\game). Copied pt-pc files keep an MIT header naming the source path and commit 8966e89.
5. Data tools: Python in repository\tools\ with a header comment, run with `py -3.14 -I`, paths as arguments, never from inside a read-only folder. Small metadata outputs in repository\tools\data\; anything extracted or listing game file names goes to work\ (git-ignored).
6. Each new non-trivial piece of logic gets a small test (Check() style unit test, or an assert-based self-check in a tool).
7. Tick plan boxes in place when their exit criterion is met and checked. If the plan is missing something, add "Plan changes needed" to your analysis file; do not rewrite the plan.
8. At the end, verify: citations present, ticked boxes have real output, nothing changed outside the main folder (`git --no-optional-locks status --short` in pt-pc and shadPS4), and no game data staged for commit.

Hard rules:
- Never modify, move, delete or create files in the read-only folders; read-only git commands only there.

- Ask me before installing toolchains (Vulkan SDK, etc.), creating a venv, downloading tools (Ghidra), building shadPS4 in work\, or committing.
- No online-service circumvention: online features stay off; DLC ownership comes only from my own installed add-ons.
- If blocked, write exactly what is blocked and what is needed, finish the rest, and stop.

When you finish, reply with: (1) items completed, (2) the 5 most important results, (3) files created or changed, (4) open questions or blockers, (5) the next item. Keep it short, then stop.

Language: reply in the language I write in. Write all project files in English.
