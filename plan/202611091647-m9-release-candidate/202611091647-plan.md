## R1: route player

- **Turning it on:** `--route FILE` makes `sif.exe` play a script. The commands are injected through `sif::PollEvent`, so no OS input is involved. The route ends the app with code 0 for a pass and 3 for a fail, and logs `route: PASS` or `route: FAIL line N: …`.
- **Commands** (one per line, `#` comments, pt-pc's style kept simple):

  | Command | Effect |
  |---|---|
  | `wait N` | N frames (or `wait 2s`) |
  | `key NAME` | A key press and release: Enter, Esc, Left, Right, Up, Down, PageUp, PageDown, T, Space, the lane keys `A S D F J K L ;` |
  | `expect screen NAME` | The current screen is NAME. Each `Run*` reports its name: `title`, `menu`, `select`, `live`, `result`, `costumes`, `materials`, `missions`, `profile`, `options`, `calibrate` |
  | `expect log TEXT` | The log has a line containing TEXT since the route started (for example `live result: Perfect`) |
  | `shot NAME` | Save the window's picture to `<shots>/NAME.png`, through a GPU read-back of the swapchain |
  | `timeout N` | Fail if the route runs longer than N seconds |

- **Small additions to the screens:**
  - one `SetScreen("name")` line per screen;
  - a few log lines where the screens log nothing today (choice made, setting changed, reward claimed).
- **Hidden window:** `--hidden` creates the window hidden. If `BeginFrame` fails there, use a normal window instead and record that. The routes never need focus.
- **Test:** a unit test for the script parser, and a tiny route (`wait`, `expect screen title`).

## R2: runner

- **`tools/routes.py --exe <sif.exe> --game <dump> [--only NAME] [--shots DIR]`.** For each route:
  - a fresh temp data folder, with a `settings.ini` that holds `[game] folder` and, if the route asks for one, a seed `save.txt` from `tests/routes/seeds/` (port-made text, no game data);
  - run it, read the exit code and the `route:` line.
- **Output:** a table of route, result, time and failing line. Exit 1 on any failure.
- **Hygiene:** never touches the user's `work/build/release/data`.

## R3: routes

| Route | Covers |
|---|---|
| `boot` | Logos, notice, title, then the top menu |
| `play_autoplay` | Menu → select → song, difficulty, stage, costume → live (autoplay) → result → back to select; `expect log` for the result line |
| `play_keys` | A live with lane keys pressed at fixed times; judgements are counted (not all Miss) |
| `select_back` | Esc at each select step goes back; Esc from select returns to the menu |
| `save_best` | Two runs sharing one data folder: the second shows the saved best rank and NEW only when beaten |
| `options` | Sound volume and note speed changed, written to `settings.ini`, still there after a restart |
| `controls` | Control Settings: change a lane button, restore the defaults |
| `calibrate` | 24 Space presses on the clicks; an offset is stored |
| `costumes` | Seed save with materials: Costume Materials list; create a costume; dress a member; the next live uses it |
| `missions` | Seed save with a completed mission: Task List tabs, paging, claim (GET! → COMPLETED) |
| `profile` | Change the accolade, name plate and badge; the menu header follows; saved |
| `talk` | T on the top menu plays another line (logged) |
| `languages` | `--lang cn`, `tw`, `jp`: boot to the menu without errors |
| `addons` | Add-on detection logged; an add-on song is selectable (skipped when the user's dump has none) |
| `lives_groups` | One µ's, one Aqours and one Saint Snow song, autoplay to the result, with no warnings beyond the known ones |

A route that cannot be automated is listed in the checklist instead, with the reason.

## R4: manual checklist

- **File:** `repository/docs/CHECKLIST.md`. Every screen in the analysis (§2) gets a short "look for" line and a box to tick, plus the build and first-run steps from BUILD.md and PLAY.md.
- **Evidence:** I run the routes with `--shots` and link the captures, so the user can compare them with the game.
- **Ticking:** the user ticks the boxes after their own run of the Release build.

## R5: fixes

Each failure gets a short analysis file and a small fix commit. Anything larger than a fix goes to the user as a choice: fix now, or list as a known gap in PLAY.md.

## R6: close

- All routes pass with the Release build.
- The checklist is ticked by the user.
- `no_assets_check.py . --all` is clean.
- All unit tests pass; Debug and Release are rebuilt.
- Write the analysis file; tick M9 and the completion criteria in the roadmap.

## Risks

| Risk | Mitigation |
|---|---|
| A hidden window may not render | Fall back to a normal window (R1) |
| Timing-based routes (calibration, lane keys) may be flaky | Use the audio clock that the screens already use; allow wide checks (counts, not exact grades) |
| Routes may expose real bugs that take time | R5 asks the user before anything large |
