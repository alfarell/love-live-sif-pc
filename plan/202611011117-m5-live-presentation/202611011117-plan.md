## 2. Steps

1. **Motion keys.**
   - Decode the `BMA` channel key encoding: times, values, and channel types 0/3/2.
   - Check it by posing `mod_01_honoka` with the dance motion in `bmar_dump.py` (preview PNGs at a few frames).
   - Document it in `docs/formats/bmar.md`.
2. **3D renderer path.**
   - Add to the SDL3 GPU renderer: depth buffer, a textured mesh pipeline (position, normal, uv0; `btx` textures), view/projection, CPU skinning first (shortcut, GPU palette later if slow).
   - C++ BMAR reader in `src/engine/formats/`.
   - Exit: the stage plus one character in bind pose in the live screen behind the note lanes.
3. **Dance.**
   - Play the motion on the master clock.
   - Find motion frame 0 against audio time; the *Hypothesis* is chart time 0 or the lead-in. Check against the camera and the timelines.
4. **Camera.**
   - Decode `camera_anim_0010_00_main.bmarc` (camera node track; FOV source to find).
   - Drive the view with it.
   - Exit: the live screen shows the game's camera moves.
5. **Basic effects.** Simple lighting from the `MATE` parameters and one stage light/color effect.
   - Scope set after step 4, because the effect data (`effect/`) is not surveyed.
6. **Measure:** frame time with stage + 1 character, then + 9 characters (render-cost signal).

Steps 1 and 2 do not depend on each other. Step 1 is pure format work in the Python tool; step 2 is renderer code using bind poses.
