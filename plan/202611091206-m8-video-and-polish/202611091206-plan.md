## V0: evidence

1. **Stage → monitor video:**
   - find the code that formats `movie/monitor_%03d.usm` and `movie/monitor_%03d_%c.usm` (string `0x5ED290`), and where the number and letter come from (a stage parameter, a table);
   - list the result for the stages the port offers.
2. **`ll3monitor`:**
   - disassemble its pixel shader with `tools/gcn.py`;
   - write down how the video, `monitor_dotmask` and `monitor_scrnrogo` combine;
   - find the monitor mesh names in a stage model, for example `st017`.
3. **Previews:** in a shadPS4 run of the song select and the costume screen, note where the video shows and its size, and match it to a UI part or material.

**Output:** an analysis file with the stage table and the placements. Anything unproven is labelled *Hypothesis*.

## V1: video core

- **`third_party/pl_mpeg/pl_mpeg.h`:** vendored at a fixed commit, with an entry in `THIRD_PARTY.md` (MIT text).
- **`src/engine/video/usm.{h,cpp}`:** reads a USM through `Vfs` (loose files, read in place).
  - From the `@SFV` header table it takes width, height, frame rate and frame count.
  - It joins the `@SFV` type-0 payloads into the MPEG-1 elementary stream.
- **`src/engine/video/movie.{h,cpp}`:** wraps pl_mpeg's video decoder.
  - `Open(stream)`, `Frame(n)` (decode forward; seek back to the start for a loop), and the frame as RGBA8.
  - YUV → RGB on the CPU at first.
- **`tests/unit/video_test.cpp`** (dump argument), checking:
  - `monitor_001` has 150 frames at 512 × 288, 30 fps;
  - `preview_music_0010` has 1,623 frames at 59.94 fps;
  - every decoded frame is non-empty, with a plausible mean colour;
  - all 382 files demux.
- **Optional:** a developer flag `--movie VFS_PATH` that plays one movie full screen, for checking.

## V2: streaming textures

- `Renderer::CreateTexture(w, h)` and `Renderer::UpdateTexture(texture, rgba)` through a reused transfer buffer, called outside a frame like `UpdateMesh`.
- **Test:** `--movie` shows a moving picture; a frame-cost note at 512 × 288 / 30 fps.

## V3: stage monitors

- The live loads the stage's monitor video(s) per V0 and replaces the monitor material's texture with the streamed one. The dot mask is applied as V0 finds.
- **Frame:** `floor(song_ms × fps / 1000) mod frames`, from the music clock.
- **Decode:** only when the frame index changes. If the frame cost rises noticeably, move decoding to a worker thread, as the game does with its `movie_update_thread`.
- **Test:**
  - captures of two stages with screens, against the V0 evidence;
  - frame cost against the H5 numbers (mean 18.59 ms);
  - a long song shows no drift: the frame index comes from the clock.

## V4: previews

- **Song select:** when the selected song changes, open `movie/music/preview_music_<id>.usm` and show it in the V0 placement, looping. If the file is missing, keep the cover picture.
- **Costume screens:** the same with `movie/dress/preview_costume_<id>.usm` for the focused costume.
- **Test:**
  - captures of both screens;
  - fast scrolling does not stall: only the last selection opens a movie;
  - memory stays flat while scrolling, because old movies are released.

## V5: first run

- **No valid folder:** when `[game] folder` is empty or not a dump, `main.cpp` opens SDL3's folder picker (`SDL_ShowOpenFolderDialog`) instead of only showing an error.
- **Checking the choice:**
  - the chosen folder is checked with `IsSifDump`, and the reason is shown if it fails (for example "this is the `.pkg` folder: choose the extracted `CUSA24620` folder");
  - the user can retry or quit;
  - a valid folder is saved to `settings.ini`.
- **Add-on folder:** also detected next to it (`Extracted`, `DLC`), as now.
- **`--game` still works.**
- **Scope:** the port only reads the user's own dump. Nothing about obtaining or decrypting games is added.
- **Test:**
  - start with an empty data folder: the picker shows;
  - a wrong folder gives the message;
  - the right one starts the title screen.

## Risks

| Risk | Mitigation |
|---|---|
| The stage → video rule is hard to trace | Fall back to one video per stage chosen from the evidence, as a labelled shortcut |
| Decoding on the main thread costs frame time | Measure in V3; a worker thread if needed |
| pl_mpeg rejects some stream detail | V1's test decodes all 382 files before any screen work |
