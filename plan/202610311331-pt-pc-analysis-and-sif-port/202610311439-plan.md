# Plan (revision 2): Analyze pt-pc and SIF, choose the port approach, design the roadmap

Created: 202610311439 (Asia/Jakarta). Replaces `202610311331-plan.md` (same folder) from Part 2 onward. Driver prompt: `202610311439-prompt.md` (same folder).

## Why this revision

Part 1 (`analysis/202610311425-pt-pc-survey/202610311425-analysis.md`, sections 1, 5 and 9) found that **pt-pc is not an emulator**:

- "It is not an emulator. The game logic was rebuilt in C++" (`pt-pc/README.md:23-26`). It reads only three data archives; "The eboot, modules and system files are not used" (`pt-pc/README.md:54-56`).
- There is no ELF loader, NID linker, `libkernel`/`libSce*` HLE, or GNM translation in `pt-pc/src/`. The PS4 code was studied **offline** with `tools/self2elf.py`, `tools/dynlib.py`, `tools/gcn.py`.
- Even `src/engine` is built around Fox Engine formats and P.T. data (`pt-pc/src/engine/fs/vfs.cpp:19-52`).

The first plan's Parts 2 to 5 assumed a loader, an HLE system layer, and GNM translation in pt-pc, so they would have had nothing to read. This revision:

1. Moves the SIF inventory and executable analysis **forward**. SIF's engine decides whether a pt-pc-style rewrite is realistic, so it must be known early.
2. Re-scopes the pt-pc parts to what pt-pc actually contains: offline RE tooling, data access, engine services, renderer, audio, input.
3. Adds an explicit **approach decision** (rewrite like pt-pc, emulate like shadPS4, or a hybrid) before the gap analysis.
