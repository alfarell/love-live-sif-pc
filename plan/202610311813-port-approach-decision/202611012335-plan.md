## 3. Switch signal

"Estimated remaining work is several times the time spent so far": **triggered for the full scope.**

Context for that number:
1. The 26 hours built the foundations (all formats, renderer, audio, live rules, UI runtime) that the remaining work reuses. Later work is mostly per-screen logic and content.
2. Most of the estimate (menus, collection, story, events, purchase) is breadth, not core play.
3. Plan C (hybrid on shadPS4) already runs every screen. Its known problems:
   - about half the inputs are dropped in its keyboard path;
   - extra audio delay;
   - the port would become GPL-2.0;
   - the work would turn into emulator fixes instead of a native port (decision record §2–3).

## 4. Options

| Option | Scope | Estimate | Trade-off |
|---|---|---|---|
| **A-full** | Everything in §2 | about 187 h | Complete native port; long |
| **A-core (recommended)** | Playable loop with the game's own UI: title → top menu (play entries only) → song select (20_setup: song, difficulty) → live with the game's HUD (90_ingame) → result (95_result); options; own save; all songs; pad. Engine features from §2.1 as needed | about 75 h (2.1 ≈ 33 + title, top menu, setup, ingame, result, option ≈ 40 + save/songs ≈ 8) | Under 3 times the time spent; collection, story, events, costumes and effects follow by priority after CP4 |
| **C** | Switch to the shadPS4 hybrid | Unknown: input and audio fixes, DLC listing, offline NP | Every screen at once; GPL; different project |

**Recommendation: A-core.**
- The full scope triggers the signal, but the core loop is within a small multiple of what was spent.
- It reaches a playable port with the game's own UI.
- It keeps the plan-A goals (native, own licence, pt-pc model).

CP4 (after M7) then reviews the breadth again with real per-screen times from the core screens.
