**Switch signals:**

1. "Scoring/judgement rules cannot be recovered from the eboot with reasonable effort": **not triggered**. Core rules took about one working session with Ghidra headless. Only small leftovers remain (see below).
2. "Shader/render needs dwarf the budget": **not tested yet.** The slice is 2D. CP1 counted 9 shader materials, which keeps this risk low, but the first real test is M5 (stage and character).
3. Decision record §5, "revisit if the C probe boots SIF to menus with little effort": **partly triggered.**
   - shadPS4 boots SIF without firmware modules, through the menus and into live play, with no crash in about 9 minutes.
   - It has known faults: about half of the key presses are dropped, and it adds its own audio delay.
   - This is a real point for C (see the comparison below).

## A or C now

| | A (native, continue) | C (hybrid on shadPS4) |
|---|---|---|
| State | Song play works natively; formats, audio, renderer core and live rules are done | Boots to menus and live play today; input drops and audio delay to fix |

| License | Own code (no GPL in `repository/`) | Port becomes GPL-2.0 |
| Fidelity | Each system is rebuilt from the eboot: risk of small rule gaps (like the 128 vs 121 judgement total) | Exact game logic by construction |
| Learning goal (pt-pc model) | Followed | Different project shape |

**Recommendation: continue A.** Reasons:
- The slice met its criteria with little effort.
- The eboot is readable with Ghidra, so further logic recovery looks feasible.
- A keeps the pt-pc model and license independence the project set out for.

The main unknown has moved to UI and breadth (U3, CP3). That is the next point where C becomes the better choice if the estimate is large.
